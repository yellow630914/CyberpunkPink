# CyberpunkPink 遊戲設計（總綱）

> 狀態：設計階段。這份是總綱：核心原則、遊戲迴圈、報告、AI 管線，以及**和 ElondiaRPG 的對照**（哪些沿用、哪些改寫、哪些不要）。各系統的規則在各自的文件，見 [README](README.md)。

## 1. 一句話

玩家是緋灣市的邊緣行者：接案子、改造身體、潛進網路、把看到的東西賣給觀眾，在帳單和企業之間活下去。引擎算數字，AI 寫經過。

## 2. 設計原則

前五條直接沿用 ElondiaRPG，是架構的地基：

1. **引擎是唯一真相。** 擲骰、傷害、金錢、名聲都由引擎決定並寫進報告。AI 只描寫，不改數字、不新增物品。
2. **AI 可以判定，但後果由程式夾住。** 自由行動擲骰後由 AI 決定成功程度，後果只能是封閉清單裡的效果，數值夾在上限內。
3. **報告即事件紀錄。** 每個動作產生一份報告，`changes` 套用到狀態。
4. **AI 失敗不影響遊戲。** AI 關閉時用報告顯示簡易戰報，遊戲完整可玩。
5. **世界書是設定來源，不是執行邏輯。**

後四條是這款遊戲自己的：

6. **染色不換骨。** 每個情色化的概念，底下都要有一個和原概念等價的功能。粉牆仍然是擋住失控 AI 的牆；蕾絲仍然是會殺人的防禦程式。判斷一個設定能不能用的方法：把色情的部分拿掉，它還是一個成立的賽博龐克設定嗎？
7. **同步越深，力量越大，回灌越重。** 這個世界的神經介面走快感迴路，所以「接得多深」是所有玩法共用的風險旋鈕：竄網的同步深度、機甲的同步率、義體的敏感度，都是同一個取捨。細節見 [CORE_RULES](CORE_RULES.md) 第 5 節。
8. **一案一團。** 遊戲的基本單位不是「一天」而是「一件案子」，有固定的四拍：接案、踩點、行動、收尾。每拍都能用戰鬥、竄網、社交任一條路解決。見 [FIXER](FIXER.md) 第 2 節。
9. **帳單是敵人。** 房租、義體訂閱、藥、債每週到期。高科技、低生活要用數字感受到：不接案子就會被鎖義體。

## 3. 遊戲迴圈

```
            ┌──────────────── 每週結帳：房租、義體訂閱、債、藥 ────────────────┐
            ▼                                                              │
  據點／街區（診所、黑市、夜店、人偶館、媒體台、中間人的店）                       │
     ├─ 生活：改造、買賣、保養、治療人性、經營關係、打工                         │
     ├─ 接案（從中間人，或自己當中間人開盤）                                    │
     │     └─▶ 踩點（打聽、勘查、預先駭入、收買）                               │
     │           └─▶ 行動（場景地圖：強攻／潛入／社交／竄網，可混用）            │
     │                 └─▶ 收尾（報酬、背刺、熱度、素材）──────────────────────┤
     └─ 發布素材、開直播、派人出任務（媒體與中間人的經營線）─────────────────────┘
```

- 時間以**小時**推進（ElondiaRPG 是日）。城市裡移動只花幾十分鐘，壓力來自期限與每週帳單，不是路程。
- 三條玩法不是三種職業各玩各的：一件案子通常三條都用得上，主角不會的那條由隊友或外包補上。

## 4. 和 ElondiaRPG 的對照

「沿用」表示引擎模組可以直接搬；「改寫」表示骨架留著、規則重新推導；「新做」表示 ElondiaRPG 沒有。

| ElondiaRPG | CyberpunkPink | 幅度 | 為什麼改 |
|---|---|---|---|
| 報告、`commitReport`、存檔、回退 | 相同 | 沿用 | 架構地基 |
| AI 敘事管線、世界書注入、成人場景分流 | 相同（報告種類增加） | 沿用 | |
| 主動行動（擲骰 → AI 判定 → 夾住後果） | 相同，是「主持人」層 | 沿用 | 跑團感的來源 |
| 效果模板、特質 | 相同 | 沿用 | |
| 五屬性、`mod(x)`、d20 對 DC | 六屬性＋ 18 項技能 | 改寫 | 賽博龐克跑團是技能制 |
| 等級 1–20、職業、升級三選一 | **取消等級**；路數階級＋歷練點買技能 | 改寫 | 這類題材的成長靠裝備與名聲，不靠等級 |
| 生命值、行動點、法術環 | 生命值、行動點、**RAM**（每回合回復）＋**感載**＋**人性** | 改寫 | 法術環是長休資源，駭客需要回合內的節奏 |
| 命中對迴避、13 種傷害屬性 | 加上**站位與掩體、護甲減傷與耗損、彈藥、重創** | 改寫 | 槍戰的核心是掩體與護甲 |

## 5. 報告

格式沿用 ElondiaRPG 的 `report.schema.json`，改動：

| 欄位 | 改動 |
|---|---|
| `kind` | `gig`（案子的階段結算）／`combat`／`netrun`／`action`／`event`／`broadcast`（發布與直播）／`deal`（交易與談判）／`social`／`downtime`（生活、改造、治療） |
| `time` | 第幾天、幾點（以小時計） |
| `location` | 區、街區、設施、場景格；竄網時另有 `subnet`（子網 id 與層） |
| `party` | 快照改成 `hp`、`load`（感載）、`humanity` 各一組 `[前, 後, 上限]` |
| `timeline` | 竄網的節拍標 `layer: "net"`，和現實（`meat`）的節拍照時間順序排在一起 |
| `changes` | 新增 `cred`、`fame`（豔名）、`heat`（依勢力）、`favors`（人情）、`footage`（素材）、`audience`、`cyberware`、`humanity_cap` |
| `narration` | 新增 `stream`（這一幕正在直播：觀眾數、彈幕的氣氛） |

## 6. AI 敘事管線

和 ElondiaRPG 相同：挑世界書條目 → 組提示詞（不變的在前，可快取）→ 呼叫模型。差異只有兩點：

- **雙層場景**：竄網與現實同時發生時，提示詞要求把兩邊交錯著寫（一段網內、一段現實），靠 `timeline` 的 `layer` 判斷。
- **主持人口吻**：判定請求（自由行動）的規則加一條——像跑團主持人一樣給出「是，而且／是，但是／不，但是／不，而且」四種走向，對應大成功、成功、失敗、大失敗，並在 `twist` 寫出代價或轉機。

## 7. 預定的專案結構

```
data/worldbook/   世界書（SillyTavern 格式）
data/world/       區、設施、固定 NPC、勢力
data/rules/       各系統的規則數值
schemas/          報告格式
docs/             設計文件
src/engine/       遊戲引擎（純 TypeScript）
src/narrator/     世界書挑選、提示詞、AI 服務
src/stores/       狀態與存檔
src/components/   Vue 介面
```

技術選型沿用 ElondiaRPG（Vue 3、Pinia、Vite、Vitest）。要直接從 ElondiaRPG 分支出來改，還是開新專案把模組一個個搬過來，見 [plan/ROADMAP](plan/ROADMAP.md) 的待決定第 1 項。
