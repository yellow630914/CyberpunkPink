# 程式掃描：ElondiaRPG 的結論

> 上層：[IMPLEMENTATION](IMPLEMENTATION.md) 第 3 節。相關：[MIGRATION](MIGRATION.md)、[AI_TASKS](AI_TASKS.md)。
> 掃描日期 2026-11-16，對象是 ElondiaRPG 當下的 `src/`、`data/`、測試與工具。只讀，沒有改那邊任何東西，也沒有跑測試或型別檢查；結論來自閱讀原始碼與匯入分析，幾個大檔只讀了大綱與關鍵段落。

## 0. 先講結論

1. **引擎是自給自足的，但內部纏成一團。** 引擎 147 個模組、47.7k 行，不匯入引擎以外的任何東西。但扣掉只匯入型別的邊，仍有 **86 個模組在同一個執行時的循環裡**，沒有少數幾條邊可以切開。所以不能一個個原樣搬：**少數底層模組可以原樣搬，大多數是「照設計重寫」**。
2. **最值錢的是設計，不是程式碼。** 報告與單一提交點、三段式的主動行動、封閉的效果清單加上限、內容覆蓋的快照與還原、回退重用快照，這幾個做法照搬；程式碼依新的分層重寫（第 3 節）。
3. **奇幻假設滲到最底層。** 報告的型別裡就有種族、職業、等級、魔力；提交報告時直接處理升級與公會階級。等級在引擎裡出現 244 次、職業 119 次、法術環 98 次。
4. **有幾件事比預期的好。**
   - 戰鬥本來就不用格子，只是沒有站位。
   - 行動點已經有了。
   - 檢定已經是 d20＋調整值＋熟練對 DC。
   - 已經有一條和生命值平行的第二傷害軌（慾火），結構上和感載一樣。
   - 契約系統兩個方向都有，抗拒已經要過檢定，管理面板主動觸發事件的機制也在。
   - AI 輸出的驗證都在引擎裡，而且紮實。
5. **有幾件事比預期的差。**
   - 房屋的三份擴充計畫完全沒有開始。
   - 沒有回合制的成人場景。
   - 沒有工具調用。
   - 測試幾乎都靠「人類戰士＋真實資料」建立狀態，要跟著搬得重寫。
   - 每回合結束要跑什麼、讀檔修復這些規則寫在狀態層，不在引擎。

## 1. 循環依賴

| 項目 | 數字 |
|---|---|
| 引擎模組 | 147 個、47.7k 行 |
| 含型別匯入的循環 | 100～101 個模組 |
| 只算執行時的循環 | **86 個模組**，696 條內部邊，45 對互相匯入 |
| 把 14 個樞紐的對外匯入全部清空後 | 仍剩一個 9 個模組的循環 |
| 第二個循環（`*Mods` 一組） | 7 個模組；只靠三條邊造成，把三個清理函式移到葉節點就能解開 |
| 狀態層的循環 | 6 個 store；抽出用量統計、把型別移走，大部分就解開 |

**為什麼纏在一起**

- `state.ts` 同時是**最底層的工具**（被 76 個模組匯入）和**最上層的組裝者**（開新遊戲、存檔遷移），自己又匯入 19 個功能模組。
- **提交報告**與**推進時間**直接呼叫成人向、懷孕、公會、經驗值、戰利品、記憶的邏輯，而不是讓那些功能掛鉤進來。
- `effects.ts` 匯入 30 個功能模組，又被劇情、契約等模組匯回去。
- 底層的模組也往上匯入：光照匯入狀態、劇情條件匯入成人向與裝備、裝備與特質互相匯入、隊伍與地圖互相匯入。

**新專案的對策**：從第一天就用分層加登錄表（第 3 節），功能模組之間不直接互相匯入。

## 2. 每個系統的判定

照新專案的需求判定，分五種：

| 判定 | 意思 |
|---|---|
| **照搬** | 程式幾乎不動 |
| **換皮** | 邏輯不變，改名詞與資料 |
| **照設計重寫** | 保留做法與資料模型，程式依新分層重寫 |
| **新做** | ElondiaRPG 沒有，或差太多 |
| **不要** | 不搬 |

### 2.1 地基

| 系統 | 判定 | 說明 |
|---|---|---|
| 亂數、檢定（`rng`、`checks`、`rollParts`） | 照搬 | 檢定裡把天然 20、天然 1 寫死，可以留 |
| 時間、時段 | 照搬，但要統一 | 那邊有約 17 個時間換算函式、兩種起算方式；這邊只寫一個 |
| 錢的格式 | 照搬 | 改成信用點；加現金晶片 |
| 回退、存檔、紀錄封存（`stores/undo`、`saves`、`logArchive`） | 照搬 | 存檔摘要裡的種族、職業、等級要換掉 |
| 世界包格式、內容匯入、引用檢查 | 照搬 | |
| 繁簡轉換（`script.ts`） | 照搬 | 依賴 opencc-js |
| 報告與提交（`state.commitReport`） | 照設計重寫 | 報告帶變更差異、只有一個提交點，這個做法照搬；提交時呼叫的功能改成掛鉤 |
| 效果模板（`effects.ts`） | 照設計重寫 | 改成效果登錄表：每個功能自己註冊效果種類 |
| 主動行動（`actions.ts`） | 照設計重寫 | 三段式照搬：擲骰並存起來 → AI 只能從封閉清單選、受上限 → 套用並提交。熟練度從等級來、金錢獎勵依等級算，要換掉 |
| 劇情旗標、條件、特殊任務（`storyFlags`、`story`） | 照設計重寫 | 條件判斷改成登錄表；旗標那邊有兩種寫法，這邊只留一種 |
| 資料載入（`data.ts`，2,706 行、280 個匯出） | 照設計重寫 | 拆成每個領域各自的登錄表 |
| 模組覆蓋（`mods.ts`，2,084 行） | 照設計重寫 | 快照 → 還原 → 套用的做法照搬 |
| 每回合結束的流程、讀檔修復 | 新做（移進引擎） | 那邊寫在 `stores/game.ts` 的 `run`、`afterMove`、`load` |

### 2.2 地圖與探索

| 系統 | 判定 | 說明 |
|---|---|---|
| 格子地圖（`grid.ts`，1,797 行、匯入 33 個模組） | 照設計重寫 | 資料模型很合用：字元格子加圖例、成對的連接格、地圖之間的連線，直接對應八區互相連通。要拆成地圖模型、生成器、移動尋路、踩格子後的結算四塊 |
| 固定的特殊地圖（`specialMaps`） | 照搬，加實例 | **幾乎就是委託副本**：手繪或隨機、可進出、記回程、有自己的遭遇表與首領。缺的是同一個定義開多份實例、委託結束時清掉 |
| 隨機生成（`generateSide`） | 照設計重寫 | 內海的起點。要補：更多演算法（房間加走廊等）、入口出口可設定、純佈局與依存檔佈置分開、用種子重現、節點之間的拓樸 |
| 光照、戰爭迷霧 | 換皮 | 可以改成訊號或蕾絲的可見度 |
| 城門、近郊、城鎮流程；路網；旅行；遠征；五層地下城；地下世界；樂園 | 不要 | 單一城市用不到。城鎮之間的路網可以改當公共交通的路線圖（`world.ts`） |
| 警戒與通緝（`security`） | 換皮 | 改成依勢力的敵對值；封閉的區域列舉要換 |

### 2.5 成人向、契約、家園

| 系統 | 判定 | 說明 |
|---|---|---|
| 性經歷記錄（`sexRecord`、`narrator/sexLog`） | 照搬 | 要切掉：受孕的呼叫、提示詞裡寫死的遊戲名與種族、劇情專用的修正。**它目前在回退機制之外改狀態**，改成寫入工具時一併修 |
| 成人數值（`lewd`） | 換皮 | 四項數值改成橋參數；曝露度在這裡 |
| 成人場景 | 新做 | 那邊沒有回合制，只是一個旗標加 AI 寫的文字 |
| 內容篩選 | 照設計重寫 | 那邊是模組層級的變數，不在存檔裡 |
| 主僕關係的風格（`bondStyle`） | 照搬 | 只影響敘事與事件權重 |
| 契約（`slavery`，1,205 行） | 照設計重寫並拆開 | 兩個方向都有；抗拒已經要檢定；管理面板主動觸發事件已經有（每天一次、20 個）。要改的是**同行**的假設：成為契約人時持約人被放進隊伍當隊長，很多判斷要求對方在隊伍裡。改成不同行：拿掉那些檢查，單一的待處理事件換成有期限的**指令佇列**，原本的許可、逾期、嚴格點數改當指令的期限與違約點數 |
| 契約事件（約 110 個，五個池） | 換皮 | 單一事件格式 |
| 歡場、打工（`brothel`、`work`） | 換皮 | 改成人偶館與店面 |
| 懷孕、育兒、泌乳等 7 個模組 | 不要 | 保留的模組裡只有 4 個呼叫點要切，另外約 20 處在戰鬥、效果、休息等模組 |
| **家園**（`homes`） | 重寫 | 見 2.6 節 |

### 2.6 家園：那邊做到哪裡

**三份擴充計畫（儲物、家僕、擴建）在程式碼裡完全沒有開始。**

| 項目 | 那邊 | 這邊要的 |
|---|---|---|
| 取得 | 一次買斷，四種固定房型 | 租或買；**每週帳單**裡有房租 |
| 升級 | 沒有（擴建只有草案） | 要 |
| 家具 | **有**，資料驅動，擺在格子上 | 沿用資料模型 |
| 舒適度 | 單一門檻影響長休（三段只有草案） | 沿用並擴充 |
| 儲物 | 沒有（計畫定稿但沒做） | 要 |
| 住戶 | 只有留守的隊員；同居、家僕只有計畫 | 要 |
| 訪客 | 沒有，連計畫都沒有 | 要 |
| 居家事件 | 契約事件裡只有 2 個限在家 | 要 |

建議：**資料模型照搬，程式重寫，那三份計畫當規格**。那邊的房屋綁在城鎮的格子地圖上（空地從城鎮地圖挑、門是連接格）；這邊的家是自己的一張格子地圖，不綁在城市的格子上，和地下城、子網共用格子引擎（[DOWNTIME](../systems/DOWNTIME.md) 7.4 節）。

### 2.7 AI

見 [AI_TASKS](AI_TASKS.md)。重點：

- 那邊有 13 種 AI 工作，全部走同一個入口，每次一問一答，**沒有工具調用**。
- 驗證都在引擎裡（判定、性經歷、商店、談判、名冊、NPC 消息各一個），可以直接當寫入工具的驗證器。
- 記憶與摘要**不是 AI 做的**，是程式照規則合併。
- 退路不一致：判定有逾時與重試；敘事只能手動取消；名冊、商店、談判、消息四種沒有逾時也不能中止。
- 服務商這一層可以照搬，但要改十處才能跑工具迴圈：多輪訊息、事件串流、各家的工具格式、保留 Anthropic 的思考區塊等。
- 世界名寫死在六個檔案的提示詞裡。

## 3. 新專案的分層

```
L0 型別      時間、報告、變更、時間軸、檢定、狀態骨架（只有型別，不匯入任何東西）
L1 純工具    亂數、時間、錢、清理函式（數值、整數、字串、夾值）、編號
L2 內容      載入器、內容登錄表、覆蓋（快照 → 還原 → 套用）、世界包、引用圖
L3 狀態核心  亂數狀態、背包、旗標與計數器、提交報告（套用通用的變更，再呼叫掛鉤）
L4 規則核心  檢定、效果登錄表、條件登錄表、存檔規則表
L5 行動核心  擲骰 → AI 判定的介面 → 清理（封閉清單＋上限）→ 套用；行動種類登錄表；回合流程
L6 功能      戰鬥、竄網、輿論、裝備、委託、NPC、契約、家園……只往下匯入，用登錄表把自己接上
L7 外殼      存檔槽、回退、遷移步驟表、AI 任務與工具、介面
```

**規則只有一條：L6 的功能之間要互相用到，透過 L3～L5 的掛鉤或登錄表，不直接匯入。** 用一個檢查腳本在測試時擋住違規的匯入。

## 4. 搬的順序因此變成
