# 系統盤點：哪些過過了，哪些還沒

> 上層：[ROADMAP](ROADMAP.md)。相關：[WORLD_ITEMS](WORLD_ITEMS.md)（世界觀內容的盤點）、[MIGRATION](MIGRATION.md)（ElondiaRPG 模組的盤點）。
> 這份盤點的是**設計決定**：每個系統有沒有和你討論過。不做具體設計，只列狀態。

三種狀態：

| 記號 | 意思 |
|---|---|
| ✔ | **過過了**：你明確指定或確認過方向 |
| ◇ | **寫了，但沒過過**：我自己定的，你沒有表示過意見。文件裡有內容，但可能不是你要的 |
| ✗ | **還沒寫**：只有一句話帶過，或完全沒有 |

另標「牽動」：這個決定改了之後，會連帶改到多少別的東西（高、中、低）。牽動高又還沒過的，最該先看。

## 4. 還沒寫、而且擋著別人的

表裡標 ✗ 的一共十三列：

| 擋著誰 | 還沒寫的 |
|---|---|
| 擋著 L4 的生成 | 各種內容的資料格式（十一）、委託的生成規則與報酬（六）、構裝的目錄（四）、隨機生成的規則（四）、內海的固定地圖（四） |
| 擋著平衡 | 數值平衡的方法（十一）、輿論戰的數值與平衡（五） |
| 擋著畫面 | 每個勢力的圖案與輿論戰棋盤的圖示（十一） |
| 動工前要談 | 存檔規則與難度、新手教學與開場、繁簡轉換與手機版要不要沿用（十一） |
| 可以晚一點 | 對峙（三）、內容編輯器與世界包（十一） |

其中最急的是資料格式：規則都定了，但每一種內容「一筆資料長什麼樣子」多半還沒寫，現在直接生成內容，每一批的欄位會對不起來。

## 5. 怎麼用這份

- 每過一項，把 ◇ 改成 ✔（或依你的意見改寫後再標）。
- 新寫的系統先標 ◇，等你看過。
- 建議的過法：一次拿第 3 節的一項，我用幾句話說明現在的做法與另外一兩種選擇，你決定。不必讀完整份文件。
