## 4. 實作階段

每個階段結束時都要是能玩的。三個戰場各有一個可以操作的 Demo，實作時拿它們當畫面與規則的參考：

| Demo | 對應的階段 | 規則 |
|---|---|---|
| `mockups/combat-demo.html`：四格對四格的站位與行動圓環 | M1 | [COMBAT_SYSTEM](../systems/COMBAT_SYSTEM.md) |
| `mockups/net-demo.html`：同一個站位版面，加上同步檔位與管理行動 | M3 | [CYBERSPACE](../systems/CYBERSPACE.md) 第 6 節 |
| `mockups/opinion-demo.html`：3×3 的棋盤、手牌、聲量與風向 | M5 | [OPINION](../systems/OPINION.md) 第 3、4 節 |

| 階段 | 內容 | 完成的樣子 |
|---|---|---|
| **M0 地基** | 專案骨架與分層（[CODESCAN](CODESCAN.md) 第 3 節）、狀態工廠與測試設定、報告與存檔、AI 的工具迴圈與 judge／narrate 兩個任務（[AI_TASKS](AI_TASKS.md)）、主動行動、六屬性與十八項基本功、檢定 | 可以建角，在一個空房間裡做自由行動並看到敘事 |
| **M1 槍戰** | 三條軌、行動點戰鬥、四格對四格的站位、直接減傷的護甲、五種傷害、武器（先用現成的成品，設計圖與零件的資料格式一開始就照 [CRAFTING](../gear/CRAFTING.md)）、基本義體、**敵人的等級 I～V 與位階**、技能裝在橋裡的最小版與各路數的現實面（**掮客的指揮、叫人、談在這裡就能用**，隊友先用固定的測試夥伴）、倒下與戰敗。**戰敗事件先做「略過」的版本**：成人路由的敘事寫一段，程式自動結算；內容篩選與照主角體型分兩版的分支也在這裡 | 蜂巢的一張地圖，打得起來；打輸了會進戰敗事件 |
| **M2 一案一團** | 中間人、委託的四拍、踩點（開出來的路、提前看到後面的階段）、**委託副本的階段制**（三到五個階段、每個階段選一面來玩、連動、輔助面每個階段擲一次、封閉與撤退；這一階段只有現實面可選）、名冊與召集、人情、**事件導演**（十種範圍）、街頭信譽與敵對值、身分與**掃橋**、每週帳單、最小的住處（租一間房、睡覺、付房租）、**分階段的打工**。**可以操作的成人場景也在這裡做最小版**：進入點、十種行動、基本的體位、主動權、部位的連接、玩家自己結束、契合與結算 | 可以連續接生成的委託、打工、付房租；戰敗事件與打工的成人階段可以進場景操作 |
| **M3 網路** | 內海的公共區、化身與構裝、八條路數的網路面、RAM、快駭、蕾絲、追蹤度、控制節點、同步檔位、管理行動、釘住與扣線、隨機生成（迷宮館、沉船帶）、**副本的內海面** | 全隊可以一起潛入；同一件委託的每個階段可以選現實或內海 |
| **M4 身體** | 完整的義體、**設計圖與零件的組裝**（義體、武器、護甲；機械與生體）、邊緣橋的型號與技能容量、沉溺與溺感、粉牆與流竄 AI 的蠱惑、授權鎖、惡意韌體、橋參數與傾向的成長、調校、**夜課**（第九棵技能樹、體悟、靠技能開放的體位）、多人分圈的成人場景、場所、契約與橋權 | 改造與成人向內容完整；可以自己配橋 |
| **M5 經營** | **輿論戰**（3×3 棋盤的議題戰役；頻道的經營層）、**副本的輿論面**、媒體（錄影、把紀錄做成素材、剪片、發布）、**直播**（疊在戰鬥、副本、成人場景、日常上的一層）、偶像、簡化的派工、**房間制的家園**（升級、家具、住戶、訪客、店面、會被闖） | 主播與偶像可玩；三個戰場齊全 |
| **M6 終局** | 牆外的群落與當中間人的五個流竄 AI、機甲、主線 | 主線可以破關 |
| **M7 開放** | 內容編輯器、世界包、手機版 | 和 ElondiaRPG 同等的自訂能力 |

排序的理由：

- M1～M3 把「戰鬥、委託、竄網」三根柱子立起來。
- **掮客已經改成現實戰場的指揮**，獨立的經營玩法（盤口）刪掉了，所以他的技能跟著 M1 的現實戰鬥一起做，名冊與召集跟著 M2 的委託一起做，不再等 M5。
- **大部分的戰敗事件是成人向的**，而戰敗從 M1 就會發生。所以成人內容不能整塊排在 M4：M1 先有略過版（敘事加自動結算），M2 就有可以操作的最小版，M4 才補上夜課、多人分圈、調校、場所與契約。成人場景用的數值（感載、餘韻、橋參數）本來就從 M1 存在。
- 媒體依賴委託的流程與事件，直播是疊在其他玩法上的一層，所以排在那些玩法都能玩之後。
- 這張表和 [MIGRATION](MIGRATION.md) 第 6 節的搬遷順序是對齊的；改其中一份時另一份要一起改。
