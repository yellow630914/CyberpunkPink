## 0. 結論先講

- 全專案的 LLM 呼叫只有**兩個入口**：`streamNarration()`（串流）與包它的 `completeText()`（`src/narrator/providers.ts`）。所有請求都是**單輪 `{system, user}`**，沒有多輪訊息、沒有任何 tool use、沒有結構化輸出（`response_format`／`responseSchema` 都沒用；grep 過）。
- 共 **13 個不同的 AI 任務**（文件 `PROMPTS.md` 第 1 節標題寫「九種請求」，表格其實有 10 列，另有分鏡、續寫、連線測試沒單獨列）。
- AI 與程式交換資料的方式有三種：① 純文字正文；② 正文尾端的 `<relationship_updates>` 標籤；③ 整份 JSON（用 `extractJson` 從文字裡挖第一個 `{…}`）。
- **記憶／摘要不是 AI**：`social.recordMemory` 直接拿 `report.outcome.summary`，`compactMemories` 是規則合併。`engine/look.ts`、`engine/pcWords.ts` 也不是 AI（外貌欄位整理、依性別換字）。
- 驗證都在 engine（`sanitizeJudgment`、`applySexUpdates`、`applyAiDeals`…），品質不錯，是新專案寫入工具可以直接沿用的核心。

### 1.3 輸出、驗證、失敗時的處理

| # | 輸出 schema | 程式的驗證與夾值 | AI 關閉／逾時／格式錯 |
|---|---|---|---|
| A 系列 | 正文；尾端可有 `<relationship_updates>[{"id","to_player"}]</relationship_updates>` | `splitSuggestions`（JSON 壞掉就丟棄）、`social.addSuggestions`（id 要在 relationships、≤120 字、同人只留最新、**玩家確認後才寫入**）；`applyRegex`（預設刪 `<think…>`）；串流中 `visibleNarration`／`streamingView` 把標籤藏起來 | 關閉：畫面用 `describe.ts` 的規則戰報。失敗／取消：`entry.status='error'`，留下已清理的半段。**沒有閒置逾時**，只能手動取消。續寫出錯會還原成續寫前的正文 |
| B | `{degree, attr, skill, dc, rationale, twist, summary, narrative, adult_scene, findings, difficulty, hours, effects[], relationship_updates[], invention?, perk?}` | `sanitizeJudgment`：attr／skill 不合法退回預設；dc 夾在參考 DC ±`dc_adjust`；degree 不合法時用骰值算；`naturalCritOnly` 收斂；只留這種行動允許的效果；每種效果各自夾值（見下表）；被截掉的寫進 `adjusted`，並丟掉判定寫的 narrative 讓寫手重寫；文字欄位各有字數上限 | 關閉：`resolveAction(state, null)`→ `defaultEffects`（規則）。閒置逾時 `judgeTimeoutMin`（預設 3 分鐘，每收到一段文字或思考重設）。失敗／取消／逾時：**保留 `pendingAction`**，顯示錯誤，可重試或改用規則。換局用 `gameEpoch` 作廢 |
| B1 | `invention:{name,desc,qty,use|furniture}` | `invention.sanitizeDesign(raw, inventCaps(...))` 依 degree 的上限降值、拿掉不能用的效果 | 失敗／大失敗忽略；格式不對→做不出東西（未逐行驗證） |
| B2 | `perk:{name,desc,effects[]}` | `sanitizePerk(raw, id, cap)`：只留好處、最多 N 個效果、強度超過從最後一個減弱 | 同上 |
| C | `{npcs:[{id,name,appearance,personality,background,occupation}]}` | 只收這次送出的 id；名字不重複才用；各欄位截字；送出的人一律標 `flavored`（不重問） | 失敗：錯誤訊息，沿用規則產生的草稿。沒有逾時、不能取消 |
| D | `{deals:[{title,desc,gives[],gets[],stock}]}` | `applyAiDeals`：種類白名單、目錄物品照目錄價、自創物品價格夾在類別區間、裝備經 `sanitizeGearSpec`、筆數與 stock 上限… | `aiTried` 先設 true，失敗就用規則清單，當天不再試。沒有逾時 |
| E | `{options:[{label,attr,dc,cost_cc}]}` | attr 白名單、dc 夾 ±`dc_adjust`、cost 上限、最多 5 個、少於 2 個就不採用 | 失敗：用模板預設的方式。沒有逾時 |
| H | `{news:[{id,day,story}]}` | `applyNewsStories`：id 要有未寫的近況、≤400 字、合併同人較早的未寫條目 | 失敗：保留規則寫的短句。沒有逾時 |
| I | `{records:[{id,sex,service,solo,with[{name,id,gender,sex,service}],forced,summary,first_time,favorite,notes}]}` | `applySexUpdates`：只收 `sexCandidates`；次數／對象數上限；對象 id 要存在；文字截字；每人一筆；之後 `maybeConceive`；`markSexLogged` 防重複；等待期間換檔或回退就不寫 | 和判定共用閒置逾時；失敗可在日誌上再按一次 |
| F | 依 `output`：tags／text | `cleanTags`（去程式碼框、去重）；空的就丟錯 | 沒選預處理就原樣用語意描述 |

## 2. 服務層（`providers.ts`、`providerInfo.ts`、`vertexAuth.ts`、`connectionHint.ts`）

| 項目 | 現況 |
|---|---|
| 支援 | `anthropic`（`@anthropic-ai/sdk`，`messages.stream`）、`openai`（`chat.completions`，不是 Responses API）、`openai_compatible`（同 SDK＋baseURL；內建 OpenRouter、DeepSeek、GLM、千問、Kimi、Ollama、LM Studio）、`gemini`（`@google/genai`）、`vertex`（API key 走 SDK；服務帳戶 JSON 在瀏覽器簽 JWT 換 token，直接打 REST SSE）。SDK 都是動態載入，請求從瀏覽器直連 |
| 介面 | `Prompt = {system, user, sections?}`；`streamNarration(provider, config, prompt, signal, onUsage, onThinking): AsyncGenerator<string>`；`completeText` 只是把串流接起來，多一個 `onChunk` |
| 串流 | 只吐文字。思考另走 `onThinking`（Anthropic `thinking_delta`、OpenAI 相容的 `reasoning_content`／`reasoning`、Gemini `part.thought`） |
| 取消 | 呼叫端建 `AbortController`，signal 傳給 SDK／fetch。C、D、E、H 沒傳 signal（不能取消） |
| 逾時 | 服務層沒有。`game.ts` 的 `judge()` 與 `recordSex()` 各自寫了一份「閒置逾時」（靠 `onChunk`／`onThinking` 重設）。敘事、設計類、分鏡都沒有 |
| token 統計 | `TokenUsage {input, output, cached}`：Anthropic 由 `finalMessage().usage` 合計（input 含快取讀寫）；OpenAI 要 `stream_options.include_usage`（相容服務有回才記）；Gemini 取最後一段 `usageMetadata`。`game.addUsage(key, u, origin)` 依日誌 id 或 `_other` 累計，並依 feature／來源／模型分帳；`usageCollector` 先收、事後決定記在哪則日誌 |
| 快取 | Anthropic：整個 system 一個 `cache_control: ephemeral` 斷點。`openai_compatible`：`cacheMarkFor` 依模型名／baseURL 猜要不要在 system 標 `cache_control`（可選 1 小時）。OpenAI、Gemini 靠服務自動快取。提示詞組合刻意把少變的放 system |
| 思考參數 | `anthropicThinking`（adaptive／budget）、`geminiThinking`、`openAIReasoningBody`（5 種寫法＋`extraBody`） |
| 拒絕 | `NarrationRefusedError`（Anthropic `stop_reason==='refusal'`、OpenAI `content_filter`、Gemini `blockReason`）；特定 Claude 模型開 `server-side-fallback` beta |
| 錯誤說明 | `explainConnection` 把「Failed to fetch」類的錯誤換成 CORS／本機服務／混合內容的中文說明 |
| tool use | **完全沒有**。沒有工具定義、沒有 tool_use／tool_result 的處理、沒有多輪 messages |

要做「有工具的對話迴圈」得改的地方：

1. `Prompt` 要能表示多輪：`messages[]`，內容區塊含 text／thinking／tool_use／tool_result。目前 `vertexBody(config, system, user)`、`openAIMessages` 都寫死一輪。
2. 串流要吐事件而不是字串：`text`、`thinking`、`tool_call`（OpenAI 的 `tool_calls` 參數是分段 JSON，要自己累加）、`stop`、`usage`。
3. 每家各自的工具格式轉換：Anthropic `tools[].input_schema`、OpenAI `tools[].function.parameters`、Gemini／Vertex `functionDeclarations` 與 `functionCall`／`functionResponse`。
4. Anthropic 開思考時，回傳 tool_result 的那一輪要把上一輪 assistant 的 thinking 區塊原樣帶回；現在 thinking 只當顯示文字丟給 `onThinking`，沒保留。
5. 快取：斷點要放在「工具定義＋system」之後，迴圈中再往最後一則訊息移；現在只有 system 一個斷點。
6. `openai_compatible` 要偵測支不支援工具，不支援退回現在的 JSON 做法（計畫已要求兩種並存）。
7. 迴圈層：最多 N 次工具呼叫、每輪 `onUsage` 累加（`addUsage` 會把 `calls` 加一，算帳時要決定算一次還是多次）、閒置逾時在等工具執行時也要重設、一個 signal 管整個迴圈。
8. 寫入工具的結果先排隊，正文結束後在同一個 `game.run()` 裡套用，回退才會一起還原（`snapshotState`／`undoStack`）。現在 `recordSex` 是在 `run()` 外面直接改 state 再 `save()`，沒進回退堆疊。
9. 簡體輸出：`toOutputScript` 依 `sections` 轉換；工具結果也要走同一個轉換。
10. 伺服器端拒絕備援 beta 與工具並用的行為沒查證。

| 區塊模型 | `PromptSection {key, title, part:'system'|'user', text, attach?}`；`assemble()` 略過空區塊、依 part 接起來；`sections` 留著給預覽與繁簡轉換用 | `prompt.ts` |

| 玩家可編 | `PromptConfig`：文風條目、自訂條目（前段／後段、套用對象 narration／adult／judge、成人旗標）、世界書覆寫與新增、`loreInJudge`、篇幅、視角、銜接、變化寫法、三份規則全文（`{{language}}`、`{{currency}}`、`{{player}}`、`{{style}}`）、正則；多組「提示詞組」可切換；可匯入 SillyTavern 預設 | `promptConfig.ts`、`tavernPreset.ts`、`stores/prompts.ts` |
