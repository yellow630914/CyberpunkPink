# 系列：把事件、線索、特殊任務、委託副本串起來

> 上層：[GAME_DESIGN](../GAME_DESIGN.md)。依賴：[EVENTS](EVENTS.md)（事件與導演）、[COMMISSIONS](COMMISSIONS.md)（委託副本）、[STORY_QUESTS](../world/STORY_QUESTS.md)（特殊任務的寫法與旗標）、[FIXER](FIXER.md)（中間人、踩點與未知清單）、[AI_TASKS](../plan/AI_TASKS.md)（任務鏈與 Agent 開關）。被依賴：[STORY_QUESTS](../world/STORY_QUESTS.md)、[UI](../art/UI.md)（冒險筆記）。
> 來源：ElondiaRPG 的特殊任務與劇情旗標、線索池與線索事件、情報、期限（[plan/MIGRATION](../plan/MIGRATION.md) F、G 組）。ElondiaRPG **沒有系列的概念**：事件、線索、特殊任務、委託各自獨立，串連靠散在各處的旗標。預定資料：`data/series/*.json`、`data/rules/leads.json`。數值都是初稿。

## 1. 為什麼要有系列

四種內容各自好用，但彼此之間只靠旗標暗中牽線：一件事件立了旗標，某個特殊任務的任務點讀到它才出現；一則線索指向一件委託，委託做完又要另一個旗標去開下一步。寫的人要記得每條線散在哪幾個檔案，玩的人在筆記裡看到的是一堆互不相干的條目。

**系列是一個容器**：把屬於同一件事的事件、線索、任務點、委託副本放在同一份資料裡，畫成一張有階段的圖。

- **寫的時候**：一條線＝一個檔案。打開就看得到它從哪裡開始、經過哪些步驟、有幾個結局、用了哪些旗標。
- **玩的時候**：冒險筆記裡一個系列一頁，底下掛著它的線索、進行中的委託、已經發生的事。
- **整理的時候**：每一件內容都屬於某一個系列（或明確標成「單發」），可以依系列列出、檢查、停用、匯出。

## 2. 五種內容與它們的關係

| 單位 | 是什麼 | 誰排程 | 會重複 | 在系列裡的角色 |
|---|---|---|---|---|
| **事件** | 某個時刻發生的一件事，有選項 | 事件導演（[EVENTS](EVENTS.md) 第 3 節） | 會 | 一個節點：「在這裡、這種情況下，發生這件事」 |
| **線索** | 「某處有某事」的一則消息：還不是事，是指向事的箭頭 | 線索池（第 5 節） | 會 | 一個節點：玩家知道了，才去得了下一步 |
| **任務點** | 特殊任務的一步：固定地點的劇情、檢定、戰鬥、選擇 | 系列自己 | 不會 | 一個節點，人工寫的 |
| **委託副本** | 一件委託的行動：獨立的地圖、主面、三條指標 | 中間人或流竄 AI 發出，副本系統執行 | 會 | 一個節點：系列指定一件委託，它的結果決定往哪走 |
| **系列** | 上面四種串成的一張圖，有階段與結局 | 系列自己 | 依類型（第 3 節） | 容器 |

**特殊任務＝人工寫的系列。** 原本的「特殊任務」不再是另一套東西：它就是一個節點大多是任務點的系列。舊的寫法（開頭＋任務點＋報酬，[STORY_QUESTS](../world/STORY_QUESTS.md) 1.1 節）照用，只是放進系列的格式裡。

**單發的內容**：大部分街頭事件、一般委託、線索池裡隨機的線索不屬於任何系列，標成 `series: null`。它們是城市的日常；系列是城市的故事。

## 3. 系列的種類

| 種類 | 誰寫 | 例子 | 會不會重複 |
|---|---|---|---|
| **故事系列** | 人工 | 路數的線、中間人的線、夥伴的關係線、流竄 AI 的線、勢力的線、吉祥物 | 不會 |
| **史詩** | 人工 | 遊戲後期讀計數器收尾的大線（[STORY_QUESTS](../world/STORY_QUESTS.md) 第 2 節）。**還沒定** | 不會 |
| **委託系列** | 模板＋生成 | 同一個委託人的三件連續委託：「先偷帳本 → 照帳本找到倉庫 → 搶在對方搬走前清空」 | 會；每次的人、地點、勢力不同 |
| **生活系列** | 模板 | 一位鄰居的小事、一間店的興衰、名冊上一個人出事 | 會，條件不同 |
| **契約系列** | 模板 | 持約人的一串指令（[EVENTS](EVENTS.md) 4.5 節）：「先去換那件義體 → 再去見那個人 → 回來報告」 | 每份契約一條 |

## 4. 系列的格式

### 4.1 系列本身

| 欄位 | 說明 |
|---|---|
| `id`、`name` | 唯一；旗標的前綴就是 id（4.4 節） |
| `kind` | 第 3 節的種類 |
| `start` | 怎麼開始：`auto`（條件成立）、`npc`（某人在身邊）、`block`（走進某街區）、`event`（某件事件的某個結果）、`lead`（玩家得知某則線索）、`commission`（某件委託的結果）、`rogue`（流竄 AI 開口）、`board`（牆報）、`contract`（簽下契約） |
| `requires` | 開始的條件（和事件同一套，[EVENTS](EVENTS.md) 2.2 節） |
| `stages` | 階段：玩家在筆記裡看到的大段落（「第一階段：找到她」）。每個階段由一組節點構成 |
| `nodes` | 節點（4.2 節） |
| `endings` | 結局：哪個節點的哪個結果算哪個結局，以及結局的報酬與計數器（4.5 節） |
| `deadline` | 整條線的期限（選填）：曆法上的日子或從開始算幾天 |
| `tags` | 內容標籤；成人的題材照 [LEWD_SYSTEM](LEWD_SYSTEM.md) 第 9 節，關掉時整條線或某個分支不出現 |
| `journal` | 筆記裡的標題、每個階段的一句話 |

### 4.2 節點

每個節點是五種之一，外加兩種控制用的：

| `type` | 指向 | 怎麼「發生」 | 結果 |
|---|---|---|---|
| `event` | 一件事件（寫在節點裡，或引用事件資料的 id） | 交給事件導演，**排定**在指定的地點與時段（第 6 節） | 事件選項的結果 |
| `lead` | 一則線索 | 放進線索池，或直接給玩家（某人告訴你） | 玩家「得知」它；或它過期 |
| `point` | 一個任務點 | 在固定地點、條件成立時出現 | 任務點的結果（成功、失敗、各選項） |
| `commission` | 一件委託：固定的模板，或一組生成參數 | 由指定的中間人或流竄 AI 發出；玩家接或不接 | 委託的結局：主面達成、部分達成、失敗、放棄（[COMMISSIONS](COMMISSIONS.md) 第 8 節） |
| `opinion` | 一場腳本化的輿論戰 | 坐上編輯台時開打 | 輿論面的結局 |
| `wait` | 等：幾天、曆法上的某天、某個條件成立 | 時間到或條件成立 | 一個 |
| `gate` | 分歧：依條件走不同的下一步 | 立刻判斷 | 依條件 |

每個節點有：

| 欄位 | 說明 |
|---|---|
| `id` | 系列內唯一 |
| `after` | 前置：哪些節點的哪些結果。`all`（全部）或 `any`（任一個）；這是「接在誰後面」 |
| `where`、`when` | 地點與時段（`event`、`point`、`commission` 的入口） |
| `requires` | 額外的條件（例：某個夥伴在隊上、街頭信譽到某一階） |
| `outcomes` | 每個結果：立哪些旗標、動哪些計數器、給什麼、往哪走 |
| `expires` | 多久不處理就過期；過期也是一種結果，可以接分支 |
| `missable` | 過期或被跳過時，整條線是否還能走（可錯過的記號沿用 [STORY_QUESTS](../world/STORY_QUESTS.md) 1.3 節） |

**圖可以分岔、可以並行、可以合流。** 同一時間可以有好幾個節點是開著的：例如「去偷帳本」（委託）和「在牆報上打聽倉庫」（線索）同時開著，兩個都完成才接下一步（`after: all`），或任一個完成就接（`after: any`）。

### 4.3 節點的狀態

| 狀態 | 意思 | 筆記裡 |
|---|---|---|
| 未開 | 前置還沒完成 | 不顯示 |
| 待命 | 前置完成，還沒「發生」（等地點、時段、條件，或線索還沒被知道） | 顯示提示，或不顯示（看節點設定） |
| 進行中 | 玩家正在處理：事件在視窗裡、委託已接、任務點已開始 | 顯示 |
| 完成 | 有了結果 | 顯示結果的一句話 |
| 過期／錯過 | 期限過了，或被別的結果關掉 | 顯示，標灰 |

### 4.4 旗標與計數器

- **旗標以系列為命名空間**：`s:<系列 id>:<名稱>`。系列裡的節點讀寫自己的旗標不用寫前綴；讀別的系列的旗標要寫全名。這樣一個系列可以整個停用或刪除，不會留下孤兒旗標。
- **節點的結果本身就是旗標**：`s:<系列>:<節點>=<結果>` 自動記下，不用另外寫「完成了 A」的旗標。
- **劇情計數器**是全域的（[STORY_QUESTS](../world/STORY_QUESTS.md) 1.2 節）。故事系列的結局推動它們；史詩讀它們。
- 舊的 `story:<名稱>` 旗標照用，等同沒有系列的旗標。

### 4.5 結局

- 一個系列可以有好幾個結局。結局寫報酬、計數器的變化、勢力的好感與熱度、解鎖什麼（別的系列、商店的貨、名冊上的人）。
- **結局可以開另一個系列**：一條線的結尾是另一條線的開頭（`start.kind: series`）。這是長篇故事的串法：不寫一條巨大的系列，而是幾條接力。
- 系列結束時，筆記裡那一頁收進「已完成」，可以重讀經過。

## 5. 線索

線索是「玩家知道某處有某事」。它是讓城市感覺比玩家眼前大的東西，也是系列裡最常用的連接。

### 5.1 線索的格式

| 欄位 | 說明 |
|---|---|
| `id` | 唯一；知道之後以同一個 id 記進筆記 |
| `points_to` | 指向什麼：一件事件、一個任務點、一件委託、一個系列的開頭、一處藏東西的地方、一個人在哪裡 |
| `where` | 在哪：區、街區、要地與樓層、內海的區 |
| `hint` | 玩家看到的一句話（「舊港的倉庫最近半夜有車進出」） |
| `truth` | 是真是假：真、半真、假（假的線索指向陷阱或什麼都沒有） |
| `source` | 誰說的：牆報、中間人、打聽、線人、讀橋、事件的結果、系列的節點、AI 的鉤子 |
| `expires` | 幾天後失效 |
| `series` | 屬於哪個系列；隨機的是 `null` |

### 5.2 狀態

| 狀態 | 意思 |
|---|---|
| 隱藏 | 存在，玩家不知道。**走到那裡照樣會碰到**（沿用 ElondiaRPG：不知道也會遇到） |
| 已知 | 玩家知道了。記進筆記，地圖上有標記 |
| 完成 | 它指向的事處理了 |
| 過期 | 期限過了。指向的事可能還在，也可能已經被別人處理掉（記一則近況） |

### 5.3 線索池

沿用 ElondiaRPG 的地區線索池（[MIGRATION](../plan/MIGRATION.md) F 組），改成**每區一個池**：

- 玩家第一次進那一區時擲一批，之後每週一換一批。每批 6 格，約三成空著。
- 隨機的格子照權重抽：一件線索事件、一處藏東西的地方、一個不該在那裡的人、一件小委託的機會、一個流動攤販。
- **系列的 `lead` 節點優先放進池子**，不佔隨機的格子。
- 分一部分給這一區的消息管道（牆報、中間人、線人），其他隱藏。

### 5.4 怎麼得知

| 方式 | 得到什麼 |
|---|---|
| 牆報 | 這一區公開的線索，常常是半真 |
| 中間人 | 分給他的線索；要錢或人情 |
| 打聽（交涉檢定，在酒吧、潛艙店、同人夜市） | 揭開一則隱藏的，大成功兩則 |
| 線人（編制，[OPINION](OPINION.md) 第 2 節） | 每週自動帶回一則 |
| 快駭讀橋（[NPC_SYSTEM](NPC_SYSTEM.md)） | 這個人知道的線索 |
| 委託的踩點（[FIXER](FIXER.md) 第 2 節） | 未知清單是**這件委託專屬的線索**：同一個格式，`points_to` 是委託內的某個未知項 |
| 事件與任務點的結果 | 照寫 |
| AI 的鉤子（Agent 模式開著時，[AI_TASKS](../plan/AI_TASKS.md) 1.2 節） | `add_hook` 變成一則線索；只能放進開著 `ai_hook` 的系列節點，或當成單發 |

## 6. 系列和事件導演怎麼合作

- **系列的 `event` 節點不靠機率**：它是「排定」的。條件、地點、時段都對了，導演就把它放進候選的最前面。
- 但它**照樣受導演的上限管**：每回合最多一件擋住行動的事件、一天最多幾件（[EVENTS](EVENTS.md) 3.4 節）。系列的事件在優先序裡排在委託副本內、契約強制之後，在一般街頭事件之前。
- 被擠掉的系列事件留到下一個觸發點，不會消失，除非它有期限。
- **「事件只能連一層」的限制保留**（[EVENTS](EVENTS.md) 第 5 節）：要更長的連鎖，寫成系列。

## 7. 系列和委託副本怎麼合作

- 系列的 `commission` 節點讓**指定的中間人或流竄 AI** 發出那件委託。玩家不接也是一種結果（可以設期限，過了就由別人做掉）。
- 委託的**結局分級**（主面達成、部分達成、失敗、放棄）都可以接不同的下一步。**輔助面做了什麼也是結果**：「這件委託你有沒有在內海順手拿到那份檔案」可以開一條支線。
- **委託系列**由模板生成：一個委託人、一個目標勢力、三件委託。前一件的結果改寫後一件的條件（帳本拿到了，下一件的未知清單少一半；帳本沒拿到，下一件多一個敵人）。
- 一般委託（單發）照舊由中間人依區與信譽生成（[COMMISSIONS](COMMISSIONS.md) 第 9 節），不屬於系列。

## 8. 任務鏈與 Agent 模式

- 系列是**資料**，推進它的是程式。Agent 模式關著時，系列完全照資料走：哪個節點開、哪件事件排進去、哪件委託發出，都由程式判斷（[AI_TASKS](../plan/AI_TASKS.md) 1.1 節）。
- AI 在系列裡只做兩件事：替節點寫文字（`narrate`），以及在 `point` 與 `event` 節點的自由回應裡判定（`judge`）。結果仍然只能落在節點寫好的結果裡。
- Agent 模式開著時，AI 可以：
  - 在標了 `ai_hook` 的節點上留一則線索（例：讓下一步的人出現在一個合理的地方）。
  - 提議一件單發的事件，把一個已經開著的系列往前推（例：讓等著的那個人主動找上門）。只能推到節點寫好的下一步，不能新增結局。
  - AI 不能新增系列、不能改系列的圖。

## 9. 冒險筆記

| 頁籤 | 內容 |
|---|---|
| 系列 | 進行中的系列，一個一頁：階段、目前開著的節點、相關的線索與委託、期限 |
| 線索 | 已知的線索，依區分組；有效、傳聞（半真或假）、完成與過期 |
| 委託 | 進行中的委託；屬於系列的標出是哪一個 |
| 已完成 | 結束的系列與它們的結局 |

畫面的版面見 [UI](../art/UI.md)。

## 10. 編輯器

- 系列在編輯器裡是一張**節點圖**：節點是方塊，`after` 是箭頭，顏色表示種類（事件、線索、任務點、委託、輿論戰、等、分歧）。
- 檢查：沒有出口的節點、走不到的節點、引用了不存在的事件或委託模板、旗標拼錯、結局沒有被任何路徑走到。
- 一個系列一個檔案，可以單獨匯出成世界包的一部分。

## 11. 例子：委託系列「帳本」

```
[委託] 偷帳本（舊港，胭脂堂的倉庫辦公室；主面現實）
   ├─ 主面達成 ──────────────┐
   └─ 失敗或放棄 ──→ [線索] 帳本被搬去哪了（牆報，半真；3 天） ──→ [事件] 碼頭上看到搬帳本的人
                                                                    │
[線索] 倉庫的位置（帳本裡寫的，或事件裡問到的） ←─────────────────────┘
   └─ 得知 ──→ [等] 星期五深夜（運貨的時間）
                 └─→ [委託] 清空倉庫（主面現實；輔助面內海：關掉倉庫的攝影機）
                        ├─ 主面達成 → 結局 A：胭脂堂的熱度 +20，委託人的好感 +15
                        └─ 失敗 → 結局 B：貨被搬走，委託人另找人，好感 −10
```

## 12. 待確認

1. **特殊任務併進系列**：原本的特殊任務改成「節點大多是任務點的系列」，格式照用。
2. **單發與系列並存**：大部分街頭事件、一般委託、隨機線索不屬於系列。
3. **旗標以系列為命名空間**（`s:<系列>:<名稱>`），節點的結果自動記成旗標。
4. **系列的事件排在優先序的第三位**：委託副本內、契約強制之後，一般街頭事件之前。
5. **線索池每區一個**，每週一換；系列的線索優先放、不佔隨機的格子。
6. **委託系列**一組三件，前一件的結果改寫後一件的條件。
7. **Agent 模式開著時**，AI 只能在標了 `ai_hook` 的節點留線索、把開著的系列往下一步推，不能新增系列或結局。
