# 系列：把事件、線索、特殊任務、委託副本分組

> 上層：[GAME_DESIGN](../GAME_DESIGN.md)。依賴：[EVENTS](EVENTS.md)（事件與導演）、[COMMISSIONS](COMMISSIONS.md)（委託副本）、[STORY_QUESTS](../world/STORY_QUESTS.md)（特殊任務、旗標與計數器）、[FIXER](FIXER.md)（中間人、踩點與未知清單）、[AI_TASKS](../plan/AI_TASKS.md)（Agent 開關）。被依賴：[STORY_QUESTS](../world/STORY_QUESTS.md)、[UI](../art/UI.md)（冒險筆記）。
> 來源：ElondiaRPG 的特殊任務與劇情旗標、線索池與線索事件、情報（[plan/MIGRATION](../plan/MIGRATION.md) F、G 組）。ElondiaRPG **沒有系列的概念**：事件、線索、特殊任務、委託各自獨立，寫的人要記得每條線散在哪幾個檔案。預定資料：`data/series/*.json`、`data/rules/leads.json`。數值都是初稿。

## 1. 系列是什麼

**系列是分組，不是邏輯。** 它把屬於同一件事的特殊任務、委託副本、事件、線索放在同一個名字底下，方便寫、方便整理、方便玩家在筆記裡看。

- **系列不管先後與條件。** 誰在誰之後、什麼條件才出現，照舊由每一件內容自己的**旗標與計數器**決定（[STORY_QUESTS](../world/STORY_QUESTS.md) 1.2 節、[EVENTS](EVENTS.md) 2.2 節）。系列不會讓一件內容出現或消失。
- **系列管的是**：這件內容屬於哪一組、它在組裡的順序與分段（只是展示用）、旗標的命名空間、筆記裡的那一頁、編輯器裡的資料夾、整組的停用與匯出。
- **單發與系列並存。** 大部分街頭事件、一般委託、隨機線索不屬於任何系列（`series: null`）；它們是城市的日常，系列是城市的故事。

## 2. 成員

| 成員 | 是什麼 | 自己的邏輯靠什麼 | 在系列裡 |
|---|---|---|---|
| **特殊任務** | 人工寫的任務鏈：開頭＋任務點＋報酬（[STORY_QUESTS](../world/STORY_QUESTS.md) 1.1 節） | 旗標、計數器 | 一個成員。特殊任務還是特殊任務，系列不改它的寫法 |
| **委託副本** | 一件委託的行動（[COMMISSIONS](COMMISSIONS.md)） | 發出的條件；結局寫旗標 | 一個成員：指定的模板或生成參數，由指定的中間人或流竄 AI 發出 |
| **事件** | 某個時刻發生的一件事（[EVENTS](EVENTS.md)） | 條件、權重、導演 | 一個成員 |
| **線索** | 「某處有某事」的消息（第 5 節） | 放進池子的條件；得知、完成、過期寫旗標 | 一個成員 |

**串連靠旗標。** 例：委託「偷帳本」的結局立 `s:ledger:steal_done`；特殊任務「清空倉庫」的開頭條件讀這個旗標；事件「碼頭上看到搬帳本的人」的條件讀 `s:ledger:steal_failed`。三件都標 `series: ledger`，所以它們在筆記、編輯器、檢查工具裡是一組——但讓它們接起來的是旗標，不是系列。

## 3. 系列的種類

系列也是分類：同一個種類的系列在筆記與編輯器裡放在一起。

| 種類 | 誰寫 | 例子 |
|---|---|---|
| **故事** | 人工 | 路數、中間人、夥伴、流竄 AI、勢力的線（[STORY_QUESTS](../world/STORY_QUESTS.md) 第 3～8 節） |
| **史詩** | 人工 | 後期讀計數器收尾的大線（[STORY_QUESTS](../world/STORY_QUESTS.md) 第 2 節）。還沒寫 |
| **委託系列** | 模板＋生成 | 同一個委託人的一連串委託，**長度不固定**：兩件、三件、五件都可以 |
| **生活** | 模板 | 一位鄰居的小事、一間店的興衰、名冊上一個人出事 |
| **契約** | 模板 | 一份契約的指令與事件（[EVENTS](EVENTS.md) 4.5 節） |

## 4. 系列的格式

| 欄位 | 說明 |
|---|---|
| `id`、`name` | 唯一。也是旗標的命名空間（4.1 節） |
| `kind` | 第 3 節的種類 |
| `members` | 成員清單：`{ type: quest／commission／event／lead, id }`。順序只用來展示 |
| `sections` | 分段（選填）：筆記裡把成員分成幾段顯示（「第一段：找到她」）。純展示，不擋任何東西 |
| `journal` | 筆記裡的標題、一句話的說明；每個分段一句話 |
| `visible_when` | 筆記裡什麼時候出現這一頁（選填，預設：第一個成員開始時） |
| `done_when` | 什麼算整組結束（選填，例如某個旗標成立）。結束後收進「已完成」 |
| `tags` | 內容標籤；成人題材照 [LEWD_SYSTEM](LEWD_SYSTEM.md) 第 9 節。整組關掉時，成員都不出現 |

### 4.1 旗標的命名空間

- 系列裡的成員寫旗標時，名稱自動加上 `s:<系列 id>:`。讀同一個系列的旗標不用寫前綴；讀別的系列的要寫全名。
- 這樣一個系列可以整組停用或刪除，不留孤兒旗標；檢查工具也能列出「這個系列讀了哪些別人的旗標」。
- **劇情計數器是全域的**，不放進命名空間（[STORY_QUESTS](../world/STORY_QUESTS.md) 1.2 節）。
- 單發的內容與舊的 `story:<名稱>` 旗標照舊。

## 5. 線索

參考 ElondiaRPG 的線索功能（地區的線索池、情報商、打聽、線索事件），改到這座城市。

### 5.1 線索的格式

| 欄位 | 說明 |
|---|---|
| `id` | 唯一；得知之後以同一個 id 記進筆記 |
| `points_to` | 指向什麼：一件事件、一件特殊任務的某個任務點、一件委託的機會、一處藏東西的地方、一個人在哪裡 |
| `where` | 區、街區、要地與樓層、內海的區 |
| `hint` | 玩家看到的一句話 |
| `truth` | 真、半真、假（假的指向陷阱或什麼都沒有） |
| `source` | 牆報、中間人、打聽、線人、讀橋、事件或任務點的結果、AI 的指引 |
| `expires` | 幾天後失效 |
| `series` | 屬於哪個系列；隨機的是 `null` |

### 5.2 線索池

沿用 ElondiaRPG 的地區線索池，改成**每區一個**：

- 第一次進那一區時擲一批，之後每週一換一批。每批 6 格，約三成空著。
- 隨機的格子照權重抽：線索事件（有登場角色的一件事）、藏東西的地方、不該在那裡的人、一件小委託的機會、流動攤販。
- **系列的線索**在條件成立時放進池子，不佔隨機的格子。
- 一部分分給這一區的消息管道（牆報、中間人、線人），其他隱藏。
- **不知道也會遇到**：走到那裡，隱藏的線索照樣在。遇到了就記進筆記（「自己遇到的」）。
- 換一批時，還沒被知道的作廢；已知的照自己的期限留著。沒人處理而過期的，有登場角色的記一則近況（[NPC_SYSTEM](NPC_SYSTEM.md)）。

### 5.3 怎麼得知

| 方式 | 得到什麼 |
|---|---|
| 牆報 | 這一區公開的線索，常常是半真 |
| 中間人 | 分給他的線索；要錢或人情 |
| 打聽（交涉檢定；酒吧、潛艙店、同人夜市；同一處一天一次） | 揭開一則隱藏的，大成功兩則 |
| 線人（[OPINION](OPINION.md) 第 2 節的編制） | 每週自動帶回一則 |
| 快駭讀橋（[NPC_SYSTEM](NPC_SYSTEM.md)） | 這個人知道的線索 |
| 委託的踩點（[FIXER](FIXER.md) 第 2 節） | 未知清單是**那件委託專屬的線索**，同一個格式 |
| 事件與任務點的結果 | 照寫 |
| AI 的指引 | 見第 7 節 |

### 5.4 線索事件

線索池擲到「事件」時，是一件有登場角色（0～2 位）的事，放在地圖上一格。登場角色一半的機會是這一區主角認識的人。走到那一格才觸發，回應方式與結果照事件的格式（[EVENTS](EVENTS.md) 第 2 節）。

## 6. 委託副本：進去了就在裡面

**委託副本進行中時，不能做副本以外的事**，像進到 MMO 的副本：

- 進了入口，主角與召集的隊員就在副本的地圖裡（現實面、內海面、輿論面的編輯台）。城市的地圖、街頭事件、商店、休息、其他委託都暫停。
- 城市那邊的時間照副本的時鐘走（[COMMISSIONS](COMMISSIONS.md) 6.2 節），但城裡的事件不觸發；契約指令的期限暫停（[EVENTS](EVENTS.md) 4.5 節）。
- 副本裡只會出現**副本內的事件**（[EVENTS](EVENTS.md) 4.4 節）。
- 出來只有三種方式：達成（出口）、撤退（放棄，照副本的放棄結算）、全員倒下（戰敗）。
- 所以**系列裡的委託副本是一個完整的段落**：進去、做完、出來，結局寫旗標，之後的內容讀那個旗標。

## 7. AI：指引與調味

照 [AI_TASKS](../plan/AI_TASKS.md) 1.2 節的兩種模式：

- **Agent 模式關**：系列與線索完全照資料走。
- **Agent 模式開**：
  - **生成的事件以單發為主**（`propose_event`）：城市的日常、街頭的小事。這是 AI 讓城市更有活力的主要方式。
  - **對系列，AI 只是調味或指引**：
    - 在標了 `ai_hook` 的成員上留一則**指引**：告訴玩家下一步大概在哪裡、該找誰（例：「聽說那個人最近常在舊港的酒吧出現」）。指引是一則 `truth: 真` 的線索，`points_to` 只能指向系列裡已經存在、條件已經成立的內容。
    - 生成一件和系列相關的單發事件當作氣氛（例：讓等著的那個人託人帶一句話），但結果**不寫系列的旗標**。
  - AI 不能新增系列、不能新增或改寫成員、不能動系列成員的旗標與計數器。

## 8. 冒險筆記

| 頁籤 | 內容 |
|---|---|
| 系列 | 進行中的系列，一個一頁，依種類分組：成員的狀態（進行中、完成、過期）、相關的線索與委託、期限 |
| 線索 | 已知的線索，依區分組；分有效、傳聞（半真或假）、完成與過期 |
| 委託 | 進行中的委託；屬於系列的標出是哪一個 |
| 已完成 | 結束的系列 |

## 9. 編輯器與檢查

- 系列是一個資料夾：打開就看到它的成員，依分段排好。
- 檢查工具依系列列出：
  - 成員讀寫了哪些旗標；
  - 有沒有讀了卻沒有人寫的旗標，或寫了卻沒有人讀的旗標；
  - 有沒有成員引用了不存在的事件、委託模板、地點。
- 一個系列可以單獨匯出成世界包的一部分。

## 10. 例子：委託系列「帳本」

| 成員 | 類型 | 條件（靠旗標） | 結局寫的旗標 |
|---|---|---|---|
| 偷帳本 | 委託副本（陸伯發出） | 和陸伯好感 20 以上 | `steal_done` 或 `steal_failed` |
| 帳本被搬去哪了 | 線索（牆報，半真） | `steal_failed` | 得知：`lost_known` |
| 碼頭上看到搬帳本的人 | 事件（舊港碼頭） | `lost_known` | `carrier_asked` |
| 倉庫的位置 | 線索 | `steal_done` 或 `carrier_asked` | 得知：`warehouse_known` |
| 清空倉庫 | 委託副本（陸伯發出，星期五深夜） | `warehouse_known` | `raid_done` 或 `raid_failed` |

`done_when: raid_done 或 raid_failed`。五件都標 `series: ledger`；讓它們接起來的是旗標。

## 12. 資料的樣子

```json
{
  "id": "ledger",
  "name": "帳本",
  "kind": "commission_series",
  "journal": { "title": "帳本", "summary": "陸伯要一本不該存在的帳本。" },
  "sections": [
    { "title": "拿到帳本", "members": ["c_steal", "l_lost", "e_carrier"] },
    { "title": "清空倉庫", "members": ["l_warehouse", "c_raid"] }
  ],
  "members": [
    { "type": "commission", "id": "c_steal" },
    { "type": "lead", "id": "l_lost" },
    { "type": "event", "id": "e_carrier" },
    { "type": "lead", "id": "l_warehouse", "ai_hook": true },
    { "type": "commission", "id": "c_raid" }
  ],
  "done_when": { "flags_any": ["raid_done", "raid_failed"] }
}
```

成員自己的資料（例：線索 `l_lost`）：

```json
{
  "id": "l_lost", "series": "ledger",
  "requires": { "flags": ["steal_failed"] },
  "where": { "district": "old_port" },
  "hint": "帳本被搬去哪了：有人說是半夜從碼頭運走的",
  "truth": "half", "source": "board", "expires": 3,
  "on_known": { "set_flags": ["lost_known"] }
}
```
