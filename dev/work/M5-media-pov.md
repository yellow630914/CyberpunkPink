# M5-media-pov：素材的視角與鏡頭來源

- 交給：cpp-feature（sonnet）。插在第七步之前（使用者 2026-11-27）。
- 規格：docs/systems/MEDIA.md 1.1、1.2、1.3、2、**2.2（新）**、3、6 節；docs/gear/ITEMS.md 第 6 節的三種攝影機；docs/log/DECISIONS.md 2026-11-27。推翻了 M5 裁決「錄影只認義體」（M5-plan 使用者裁決第 28 題）。
- 動到：`features/media`（紀錄、素材、剪、品質）、`features/live`（開播、時段直播的第一人稱）、`features/gear`（攝影機的物品與「拿著／別著／架著」的狀態，若需要）。不改核心；需要核心的東西回報。

## 要做的

1. **視角**：`RecordEntry`、`Footage`（與片的來源）多一個欄位 `pov`：`self_pov`（某人的 POV，帶 `who`）、`follow`（跟拍）、`drone`、`camera`、`cctv`（監視器）、`other_pov`（別人的 POV，帶 `who`）。素材的 view 給一句顯示用的文字（「〇〇的 POV」「無人機跟拍」……），也進 AI 的素材描述。
2. **鏡頭來源**：一件事結束時，列出在場的每一個鏡頭來源，**各記一則紀錄**（同一件事的幾則共用一個 `event` 鍵）：
   - 錄影義體：隊上每個有錄影衍生數值（現有的 `rec_grade`）的人；拍主角以外的人時是「跟拍」，拍的人是主角自己時是主角的 POV（判斷照 MEDIA 2.2）。
   - 無人機：隊上帶著、感測器有內建錄影的無人機（組裝成品的特性；若現有成品格式查不到這個特性，回報要什麼）。戰鬥中被擊落：那一則照舊記，標 `cut_short`。
   - 攝影機：三種（手持、運動、腳架），照 ITEMS 第 6 節。手持要有人拿（設計書寫的佔用規則照做）；腳架要架在這個地點。
   - 監視器、別人的 POV：只定義種類與記號；取得它們的入口留給事件（`media.record` 的 hint 可以帶 `pov`，由事件或副本給）。
   - 沒有任何鏡頭時照舊記一則沒錄到的。
3. **品質**：上限看那個鏡頭的等級（義體、無人機感測器、攝影機）；監視器上限照設計書。看點與可信的視角修正照 MEDIA 2.2 與第 3 節（POV 的親密與戰鬥看點 +1、無人機戰鬥看點 +1、監視器與別人的 POV 的可信與看點）。數字寫進 `media_rule`，資料可蓋。
4. **畫面裡有你**（`self` 記號）改由視角決定：主角自己的 POV 不算；其他視角在主角入鏡時算。
5. **多機位**：剪片時兩段以上來源素材來自同一件事（`event` 相同）且視角不同，看點 +1；不同事件拼在一起不算。
6. **直播**：開播條件改成「隊上有任何一種鏡頭來源」（錄影義體、無人機、攝影機）。開播時選用哪個鏡頭（`livePreview` 列出可選的鏡頭）；只有主角自己的錄影義體時是**第一人稱直播**：一般內容的訂閱 ×0.8（規則表），時段直播的成人那一種總熱度 +1。直播留下的紀錄，視角是開播時選的鏡頭。
7. **針孔攝影機**（ITEMS 既有，品質最高 1）：當成一種架設的攝影機，視角 `camera`，品質上限 1。

## 驗收

- 同一場戰鬥：主角裝錄影眼、隊友裝錄影眼、帶一台錄影無人機 → 三則紀錄、三種視角、共用同一件事；主角那一則 `self` 為假，另兩則為真。
- 三段素材剪在一起：兩段同一件事不同視角 → 看點 +1；換成不同事件 → 不加。
- 沒有錄影義體、只有腳架攝影機 → 可以開播，是一般直播；只有主角自己的錄影眼 → 第一人稱直播，訂閱 ×0.8、成人時段熱度 +1。
- 無人機在戰鬥中被擊落 → 那一則標 `cut_short`。
- 舊存檔沒有 `pov` 的紀錄與素材讀得進來（當成「某人的 POV」或照 `by` 推，寫在補記）。
