# M1b-random-picks（cpp-feature，sonnet）

## 目標

使用者 2026-11-23 定案：開打前要玩家選的東西一律改成**隨機**，不做「開打前選擇」的介面；預備的機制保留。

- 戰前佈置（掮客，預備）：藏貨／安排人／打點，開打時隨機一種。
- 情報網（掮客，預備）：「你指定一名敵人開場就被標記」改成隨機一名敵人。
- 黑市門路（掮客，被動）：「你指定的一名隊友」改成隨機一名隊友。
- 戰鬥直覺（槍手，招牌）：開戰時的點數隨機分到先攻、命中、迴避（每項上限照原規則）；戰鬥中仍可花 1 行動點重分配。
- 幫槍槍保養（槍手，預備）：補一個「彈匣容量 +1（最多 4）」的效果或修正（`mag_cap`），讓它能寫出來。

## 做法

- 隨機一律用 `deriveRng(state.rng, 'battle/<id>/<技能 id>')` 這類衍生亂數，同一個種子結果相同；不改變其他擲骰的順序。
- 拿掉 `actor.ext.abilities.preset` 的讀法（戰鬥直覺、黑市門路），或保留成測試用的覆寫但正式流程不寫。
- 預備的格式補 `random` 的寫法（例如 `do` 裡的 `choose` 加 `random: true`、`who: 'random_foe'`／`'random_ally'`），由做的人選最乾淨的，寫進 ADR 0015 補記。
- 示意資料 `engine/data/rules/abilities.json` 的戰前佈置、情報網、黑市門路、戰鬥直覺、幫槍槍保養照新寫法改（只動機制欄位）。
- 設計書：SKILL_TREES 槍手與掮客這五條的文字改成隨機（戰鬥直覺寫「開戰時隨機分配，戰鬥中可以重分配」），DECISIONS 記一條；`python3 tools/docs/check.py` 0 個問題。

## 驗收

- 每一項各一個測試：同種子兩次結果相同、不同種子會出現不同結果、結果落在合法範圍。
- 幫槍槍保養：下一場主武器彈匣容量 +1，到 4 為止，再下一場沒有。
- 統計表 `dev/reports/skill-effects.json` 裡這幾條的狀態跟著改（幫槍槍保養、戰前佈置、情報網從 missing 改成 done 或 approx，情報網的踩點揭開未知仍是 M2）。
