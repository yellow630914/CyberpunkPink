# M1b-loot

- 交給：cpp-feature（sonnet）
- 目標：敵人掉落的格式與打贏之後的結算：照位階決定件數、照機率抽、現金晶片照等級，寫進戰鬥結束的那一份報告。
- 規格出處：ENEMIES 第 7 節前兩條（零件的件數與機率、現金晶片的範圍）與「機器」那一條；ENEMIES 1.3 節（等級給什麼）；dev/adr/0011（戰鬥結束收成一份、骰子是導出來的）；dev/adr/0007（物品每一種一次最多 100 個、錢的上限）。整件撿、拆活人、義體、生體件、授權鎖、殘響、俘虜的處置都不在這一張（M2、M4）。
- 可以改的路徑：`engine/src/features/enemies/`（新增 `loot.ts`）、`engine/tests/features/M1b-loot.test.ts`。
- 可以用的介面：`k.battle.onEnd('enemies', fn)`（回傳 `changes` 與 `lines`）；`deriveRng(state.rng, purpose)`（`engine/src/core/util/rng.ts`；用途寫 `battle/<這一場的 id>/loot`）；物品與現金的變更（`engine/src/core/state/coreChanges.ts`）；內容種類 `item`。
- 不可以做的事：不改核心；不在戰鬥的每一步裡擲掉落（只在結束時）；不改名冊的資料（現在寫成 `{ text }` 的掉落照樣載得進來、不發東西）。

## 格式（敵人資料的 `loot`）

每一筆是下面其中一種：

- `{ item, chance, qty? }`：`item` 要查得到（任何一種物品類的內容：`item`，或零件、設計圖的 id）；`chance` 0～1；`qty` 是數字或 `[最少, 最多]`，沒寫是 1。可以加 `top: true`（這個兵種最高級的那一件：首領保證掉）。
- `{ text }`：還沒轉的敘述，收下、不發。

另外一個欄位 `cash`：`true`（預設：照等級掉現金晶片）、`false`（企業的人身上沒有現金）。

## 結算（只在結果是打贏時）

- 算誰的：被打倒、昏過去、被制伏、投降的敵人；逃走的、被帶走的（`ext.enemies.taken`）不算。
- 每個人：照 `loot` 的順序各擲一次機率，擲中的收進來，到這個位階的上限為止（雜兵 1、精英 2、首領 3）；首領沒擲中任何 `top` 的那一件時補上第一件 `top`。
- 現金：照那個人的等級在範圍裡擲（I 40～120、II 130～380、III 400～1,200、IV 1,300～3,900、V 4,000～12,000），是現金不是帳戶。
- 同一種東西合成一筆變更；`lines` 每個東西一行（「拿到 ××× ×2。」），現金一行。
- 骰子用導出來的：同一個存檔狀態結算兩次結果一樣；重來這一場之後不保證一樣。

## 驗收條件

- `chance: 1` 的兩件加 `chance: 0` 的一件：雜兵只拿到第一件（上限 1），精英拿到兩件。
- 首領的三件都沒擲中時還是有 `top` 的那一件。
- 逃走的敵人、被帶走的敵人沒有掉落；戰敗、脫離時沒有掉落。
- 現金落在那一級的範圍裡；`cash: false` 的沒有現金。
- 結束的報告裡有對的物品變更與現金變更，背包與現金真的增加；提交通過不變式檢查。
- `{ text }` 的掉落載得進來、不發東西、不丟錯；`item` 查不到的在載入時被擋，訊息裡有那個 id。
- 同一個種子跑兩次結果一樣。

## 依賴

只靠現有的敵人功能。「被帶走」的標記（`ext.enemies.taken`）由 M1b-enemy-moves 寫，這一張只讀（測試直接在單位上給）。三張都改 `features/enemies`（M1b-enemy-moves、M1b-enemy-units、這一張），不要同時做。
