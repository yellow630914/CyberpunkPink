- 交給：cpp-feature（sonnet）
- 目標：成人場景加上第十種行動「換檔」（M2 定案時留到 M3 和同步原則一起做）：用核心的同步表與「開得到哪一檔」。
- 規格出處：LEWD_SYSTEM 3.5 節（十種行動的表裡「換檔」那一列、「受到的感載照常乘上敏感度、同步檔位與體位的倍率」）、第 1 節（敏感度的門檻）；CORE_RULES 第 5 節；dev/adr/0018 第二節；dev/adr/0016 G6；dev/work/M2-scene.md（現有的九種行動）。
- 可以改的路徑：`engine/src/features/scene/`、`engine/tests/features/M3-scene-sync.test.ts`。
- 可以用的介面：核心的 `SYNC_GEARS`、`syncRuleOf`、`syncCapOf`、`syncBlock`；場景現有的回合、行動點、感載的算法與 `sceneView`。
- 不可以做的事：不 import `features/netcombat`；內海裡的成人場景不做；同步檔位不影響場景的檢定以外的東西（契合、主動權照舊），除了設計書寫的兩項：受到的感載倍率、全檔過載時沉溺 +2；精簡版（自動接線）的流程不變；共同的規定見 dev/work/M3-plan.md。

## 要做的

1. 每個參與者有一個檔位（起始是標準；上限不到標準的人是淺）；主角的上限用 `syncCapOf`，對方的上限照同一個函式算（生成的 NPC 沒有同步的等級時當 0 級：只到標準）。
2. 行動「換檔」：0 行動點、每回合一次、只能在自己的回合；選項列四檔，開不了的帶 `syncBlock` 的原因。
3. 效果：自己擲的檢定（說話、克制這類有檢定的行動）照那一檔的 `check`；受到的感載乘那一檔的 `load_pct`（和敏感度、體位的倍率相乘）；全檔每回合多回 1 點行動點、過載時沉溺 +2。
4. 對方換不換檔走規則（不呼叫 AI）：感載到上限的七成以上退一檔，否則維持；`scene_turn` 的接口留著。
5. `sceneView` 多每個人的檔位、上限與每一檔開不了的原因；結算（`scene.end`）的資料多「這一場開過的最高檔位」（橋參數的成長之後要用）。

## 驗收條件（`engine/tests/features/M3-scene-sync.test.ts`；沿用 M2-scene 測試的假體位與假對象）

- 行動的清單有十種；換檔花 0 點、一回合第二次被擋並有原因。
- 同步 3 級、敏感度 40 的主角開得了深檔、全檔灰掉並寫出缺哪個條件。
- 同一份感載在淺、標準、深、全檔受到的是 ×0.5、×1、×1.5、×2.5（其餘倍率相同時）。
- 全檔的人每回合多 1 點行動點；全檔過載沉溺 +2，深檔過載不加。
- 對方感載七成以上時他的回合開始退一檔。
- 精簡版走完一整場的結果除了檔位的欄位以外和現在一樣（沒有人換檔時逐欄相同）。
- 現有的場景測試原樣全過（「隨機走一整場」那一條保留它自己的逾時）；`npm test`、`npx tsc --noEmit`、分層檢查全過。
