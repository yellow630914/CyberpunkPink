- 交給：cpp-architect 角色（sonnet；**改的是 testkit 與測試基礎建設**）
- 目標：M3 的測試基礎建設收尾：最小的假世界加上內海要的幾筆、具名的情境、冒煙的主幹、種子重播的固定檔、分層檢查與不變式對一次。
- 規格出處：dev/test-harness.md（照它補第 1、4、6 節；第 6 節寫著「M3 加：潛入內海、一場網內戰鬥」）；dev/adr/0018；dev/invariants.md；這一批每張工單的「新的格式與鍵」。設計書不用讀。
- 可以改的路徑：`engine/src/testkit/`、`engine/tests/smoke/`、`engine/tests/repro/`、`engine/tests/fixtures/`、`engine/tests/core/layers.test.ts`、dev/test-harness.md、dev/invariants.md、`.claude/cpp/project.json`（只有路徑對不上時）。
- 不可以做的事：不改 `engine/src/core`、`engine/src/shell`、`engine/src/features`（冒煙斷在哪裡就寫 bug 報告，放 dev/bugs/，附重現的固定檔；不要自己修）；假世界不放進 `engine/data`；共同的規定見 dev/work/M3-plan.md。

## 要做的

1. **假世界加內海的幾筆**（`TEST_WORLD`，每一種只放驗主幹用得到的最少幾筆）：一副 II 級甲板、三個武器構裝（槍、近戰、干擾）、一個防護、一個工具、一支腳本、一支快駭程式；野良以外再給蜂巢的那個勢力四種蕾絲（白、粉雜兵、粉精英、閘門守衛：一碰就倒）；一筆 `net_region`（小一點的密度）、一種設施類型；一種主面是內海的委託類型與一件寫好的四階段副本（前兩階段現實與內海都可選、第三階段現實、第四階段內海下載而且是隔離區）；一件 `pinned` 的戰敗事件；（第二波有做時）一間帶潛入的設施、兩筆去處、迷宮館的小表。`worldFor` 的「拿掉哪個功能濾掉什麼」那張表跟著補。
2. **具名的情境**：`makeNetBattleGame()`（四個有甲板的化身對一場內海的一般遭遇，已經開打）、`makeNetCommissionGame()`（接了那件內海的委託、隊伍兩個人都有甲板、站在委託地點）、`makeDiveGame()`（第二波：站在潛艙店、有甲板）。小工具：`netWalkTo(game, 節點的 id)`、`netUse(game, 做什麼)`、`playNetStage(game)`（一個內海階段強攻到底：選面、選分支、走到遭遇旁邊開戰、打贏、通過閘門或做完目標）；`untilIdle` 認得內海的戰鬥。
3. **冒煙**（`engine/tests/smoke/m3.test.ts`，固定種子、AI 關著，每一條回報斷在哪一步）：
   - 內海戰鬥：開打 → 換檔 → 攻擊到一隻過載（閃斷）→ 回填 → 管理行動造牆 → 釘住 → 打贏；另一條全員拔線。
   - 委託（內海）：接案 → 出發 → 第一階段選內海、走子網、打一場、通過閘門 → 第二階段選現實 → 第三階段現實拿到開路的連動 → 第四階段內海下載 → 做完入帳；追蹤度整趟累計對得上。
   - 撤退：內海階段探索中登出 → 回到進副本之前、委託還在手上。
   - 戰敗：內海階段投降 → `pinned` 的戰敗事件 → 接受 → 委託失敗、回到進去之前；另一條選「回到這個階段開始時」，改選現實面走完。
   - 被定位：把追蹤度推到 90、走三個節點 → 委託失敗。
   - 存檔讀檔：子網走到一半、內海戰鬥打到一半、下載到一半各存一次，最後的狀態和沒有中斷的一樣。
   - （第二波）潛入：潛艙店潛入 → 自己去挖走完一層登出 → 再進去是同一張圖 → 迷宮館報新手組走完三層結算 → 登出回到現實。
   - 整體：每一份報告的前綴都在 0016 第七節與 0018 第十三節的清單裡、不變式（`observed`）沒有違規。
4. **種子重播**：內海的委託那一條（與第二波的潛入那一條）各錄一份固定檔進 `engine/tests/fixtures/repro/`；重播的執行器補上 M3 的步驟種類（`net_stage`、`net_walk`、`net_use`、`net_logout`、`dive`、`maze`）。
5. **分層檢查**：新的功能都只 import 核心；`checkExtReads` 的 ext 鍵清單補上 `netrun`、`dive`、`maze`；補一條掃原始碼的檢查：`features/` 裡註冊戰鬥行動時沒有漏寫 `modes` 的（核心的兩個除外），以及 `k.grid` 的處理函式開頭有看地圖是哪個世界的（`netrun`、`maze`、`explore` 三個功能）。
6. `m2-world.test.ts` 那張「每一個功能逐一拿掉」的表補上 M3 的功能：拿掉 `netrun` 之後委託照樣跑、內海面選不了；拿掉 `deck` 之後沒有人有 RAM、現實的快駭回到沒有甲板的樣子；拿掉 `netcombat` 之後內海戰鬥只剩核心的兩個行動。
7. dev/test-harness.md 與 dev/invariants.md 照這一批實際做出來的更新（每一條標在哪裡驗）；dev/work/M3-plan.md「每一張都適用的規定」裡能用測試守的，寫成測試。

## 驗收條件

- 冒煙的每一條通過；任何一條不過的，bug 報告裡有固定檔與會失敗的測試路徑。
- `TEST_WORLD` 帶著全部功能載入沒有錯；逐一拿掉每一個功能，其餘照樣載得起來。
- 重播的固定檔每次跑結果一樣。
- 第 5 步兩條新的檢查抓得到故意寫的反例。
- 冒煙整套仍然在一分鐘內跑完（超過的話在回報裡寫出最慢的三條）。
- `npm test`、`npx tsc --noEmit` 全過；不變式的編號連續、每一條都有出處與驗的地方。
