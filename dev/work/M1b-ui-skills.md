# M1b-ui-skills

- 交給：cpp-ui（sonnet）
- 目標：技能樹（學技能）與角色詳情的「橋」分頁（把學會的技能裝進橋）改成讀引擎（`features/abilities`），拿掉假資料與畫面裡的規則。
- 規格出處：docs/art/UI.md 8.3 節（橋的分頁）、8.4 節（技能樹；「夜課」那一段不做）、8.1 節（角色卡的抬頭與點數）；SKILLS 1.3、1.4 節（只為了看懂畫面上的字）；dev/work/M1-abilities.md 第一～三節（引擎給什麼、每一句原因的原文）。
- 可以改的路徑：`ui/src/dialogs/SkillTreeDialog.vue`、`ui/src/components/SkillTreeView.vue`、`ui/src/dialogs/character/BridgeTab.vue`、`ui/src/dialogs/CharacterDialog.vue`、`ui/src/lib/skillView.ts`（新增，純函式：把內容與狀態整理成樹與列）、`ui/src/stores/engine.ts`（只加轉接的函式）、`ui/tests/`。
- 可以用的介面（`@engine/src/features/abilities`）：`abilitiesOf`、`treeTier`、`TREE_XP`、`learnBlock`、`learn`、`capacityOf`、`equipAbilities`（不合格會丟錯，訊息就是原因）；內容種類 `path`、`ability`（從引擎的內容登錄表列出來）；做完 M1b-skill-format 之後還有 `prepBlock`、`prep`（預備）。
- 不可以做的事：不改 `engine/`；不在元件或 `lib` 裡判斷能不能學、能不能裝（問引擎）；不用 `ui/src/data/skillTypes.ts` 之類的假技能資料；夜課、體悟、調校槽、「換配置要在據點花半小時」引擎還沒有，不要自己做規則（見下面第 4 點）；技能的說明文字裡的 Markdown 粗體要轉成畫面的粗體，不要把星號印出來。

## 要做的

1. **技能樹**：左邊是內容裡有的每一棵樹（名字、招牌、哪一類容量的顏色、在這棵樹累計花的歷練點、五格的階：`treeTier`）；一點都沒花的變淡。抬頭的進度條刻度用 `TREE_XP`。樹：招牌在最上面，每一階前層、後層兩列；三條線照 `after` 的鏈排（同一條鏈一欄）。技能卡四種狀態：學會了、可以學、條件不夠（原因是 `learnBlock` 回的那一句）、那一階還沒開。共鳴五格照階數亮。
2. **詳情與學**：種類、容量、消耗（照 `use` 寫成一句）、前置、三個戰場各一列（`meat`、`net`、`opinion` 是 `null` 的變淡；標 `pending` 的寫「還沒有做成機制」）。按「學」提交 `learn` 的報告；不能學時按鈕灰掉、下面一行是引擎的原因。
3. **橋的分頁**：四條容量條（`capacityOf` 的 `used`／`max`）；清單只列學會的技能，可以照樹篩、「只看裝著的」。勾選是改一份暫存的清單，按「套用」才呼叫 `equipAbilities` 提交；游標指著還沒裝的技能時的預覽數字是「現在用掉的加上它的容量」（只做加法）；套用被引擎擋下時，那一句原因顯示在最下面一行。
4. **最下面一行**：戰鬥中、等著選戰敗的三個選擇時整頁唯讀並寫原因（store 的 `blockOf`）；其餘時候寫「可以換」。設計書寫的地點與半小時引擎還沒有，這一行不寫時間。
5. 內容裡沒有技能資料的樹（現在的示意資料只有槍手與掮客）不列；一棵都沒有時整頁寫「還沒有技能的資料。」。
6. **手機版**照 8.3、8.4 節最後一段。

## 驗收條件（測試自己寫；內容用測試自帶的最小假資料：兩棵樹、各一個招牌加三個技能、一個共鳴）

- 歷練點夠、前置學了的技能按得下去；按了之後歷練點減少、卡片變成學會了、那棵樹的累計增加，引擎的狀態一致；存檔再讀回來還在。
- 前置沒學、點數不夠、階還沒開，三種各顯示引擎回的那一句（字和 `learnBlock` 的回傳一樣）。
- 樹的累計到 40 時第二階從斜紋變成開的。
- 橋：勾了超過容量的組合按「套用」，引擎的原因顯示出來、狀態沒有變；合格的組合套用之後 `capacityOf` 的數字和畫面一樣。
- `meat` 是 `null` 的技能在「現實」那一列是淡的；標 `pending` 的有那一句說明。
- 說明文字裡的 `**字**` 顯示成粗體、畫面上沒有星號。
- 元件與 `skillView.ts` 不 import 假的技能資料，也沒有自己比歷練點或容量的判斷式（掃原始碼的測試）。
- 戰鬥中打開是唯讀的，原因是 store 給的那一句。
- `npm test` 與 `vue-tsc` 全過。

## 依賴

只靠已經做完的 `features/abilities`，可以和引擎的工單同時做。「預備」的按鈕等 M1b-skill-format 做完再補（還沒做完就不顯示，列在回報裡）。
