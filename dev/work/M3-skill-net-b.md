## 要做的

1. 四棵樹每一個技能的內海欄寫成一筆測試資料，規矩同 M3-skill-net-a。
2. 要補的通用機制，已知的：
   - **誘惑在內海**：傷害照內海的規則（加魅力的調整值）、距離 3 以內；目標要有橋——蕾絲裡只有帶 `persona` 標籤的打得到（粉色的精英與首領，資料給）。
   - **面具**：化身戴著面具時敵對值與豔名不連到本人——內海戰鬥結束時「留下痕跡」的那一類變更這一批還沒有來源，先把 `mask` 的狀態帶進內海戰鬥並在結束的報告標出來（`data.masked`）。
   - **掮客**：指揮在內海每回合最多讓 1 點；叫人改成遠端叫名冊上的一名潛網者（候補裡帶 `netrunner` 路數的人）：對一個敵人丟一次他的快駭、或替我方一格補一級防火牆，每場一次。
   - **導流階**：衍生數值 `flow_tier`（這個功能定義，基本 0；媒體的功能之後加 provider）。主播的導流技能公式裡的階數讀它；是 0 時技能照樣能用、數字照 0 階算（設計書沒有 0 階的那幾個就灰掉，原因寫「還沒有頻道。」）。洗版（追蹤度下降）用 `net.trace`。
   - **共鳴**：姿態式的連接——花 1 行動點接上最多「樹階 ＋1」名隊友，之後每回合自動維持；被接上的人受到感載時偶像可以替他承受一半（反應）；偶像過載時全部斷開，每個被接上的人受一次脫鉤衝擊（感載 +10、暈眩一回合）；開著時每回合追蹤度 +1。曲目是姿態、同時一首；偶像在淺檔時曲目的數字減半、深檔以上用「深檔以上」那一條（`when.sync_min`）。
   - **安撫**：讓蕾絲與遺魂暫時不攻擊——目標帶 `persona` 或 `program` 標籤，檢定過了給一個「不攻擊」的狀態（AI 不列攻擊類的行動）。
3. 對照表同 M3-skill-net-a。

## 驗收條件（`engine/tests/features/M3-skill-net-b.test.ts`）

- 四棵樹的測試資料全部載得進來。
- 名媛：誘惑打帶 `persona` 的粉精英有效、打沒有 `persona` 的雜兵灰掉並有原因；傷害有加魅力的調整值；距離 4 灰掉。
- 掮客：指揮一回合讓第二點被擋；遠端叫人在候補裡有潛網者時列得出來、用了之後每場一次用完；候補裡沒有人時灰掉。
- 主播：`flow_tier` 是 0 時需要導流階的技能灰掉、原因是那一句；測試加 provider 給 2 之後用得了，洗版讓追蹤度下降。
- 偶像：3 階接上四個人裡的三個（自己不算）；被接上的人受 10 點感載時偶像替他承受 5；偶像過載之後連接全斷、每個人感載 +10 並暈眩；開著時每回合追蹤度多 1；曲目在淺檔數字減半。
- 安撫成功的粉精英下一個回合不攻擊。
- 回報裡的對照表涵蓋四棵樹的每一個技能。
- 現有的技能測試原樣全過；`npm test`、`npx tsc --noEmit`、分層檢查全過。
