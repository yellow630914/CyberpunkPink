## 結論：要改

必修 2 條、應修 6 條、建議 6 條；另有 6 題規格問題要使用者決定。

沒有問題的部分（逐項對過）：

- **分層**：`features/*` 只 import `'../../core'`；沒有功能讀別的功能的 `state.ext`（拍賣讀契約、tuning 讀 `cyber.bridge` 都是經由效果的名字或報告的 `action`）。`shell/` 從 `features/scene`、`features/unreg` 匯入是 L7 往下，合法。
- **核心的改動都對得上工單與 ADR 補記**：`k.passives`（屬性、衍生數值、檢定、戰鬥修正、單位標籤各掛一次；繞圈保護；`per` 的軌道縮放；節奏資源 +1 的夾法）、`action.window`、`turn.control`（傀儡）、`damage.hp`（痛覺轉譯）、熔斷器三種標籤、`next_attack`、`sync_cap_max`、`has_item` 的 `tag`、量表條件的 `key: 'any'`。核心路徑的改動都出現在 cpp-architect 角色的工單（core-product、core-passive、core-gaps、core-scene-ai、core-part-ai、followups-2、smoke）之內；但有兩個介面工單的 commit 夾帶了核心檔案（見建議 6），從 git 上無法逐檔確認是誰改的。
- **AI 任務**：七個場景任務、`design_part`、事件的 `scene_gate`，每一個都有 `check`（驗格式、封閉清單、夾值）與規則的退路；夾值都在 `final`／`make_draft` 那一步（寫正文之前）；功能端再驗一次（`readClosing`、`performMoves`、`deliverDraft` 重跑 `textProblems` 與 `frameProblems`）。AI 關著時三個入口照功能的純函式走。玩家的文字（寫法指令、稱呼、化身描述、訂做的描述）原樣放進 prompt，是使用者的決定，不算問題。
- **內容底線**：年齡只在核心的提交與讀檔擋（`underageAt`），M4 沒有另加本端的文字篩選，符合使用者的決定。
- **存檔與回退**：M4 的新狀態都在 `state.ext`／`actor.ext`，跟著快照走；模組層的 `WeakMap` 都是「一步之內」或「每個 kernel 的查表」，不跨存檔；戰鬥中吃藥只記在單位上、戰鬥結束才寫回（重來與回退時什麼都沒發生），設計正確。`Game.unregDeliver` 在回退與讀檔時取消、pending 留著。

## 必修

### 必修 1：簾後館的場熱量表叫 `heat`，違反使用者的裁決（`stage_heat`）；M5 註冊直播熱度時會撞名

- 檔案：`engine/src/features/curtain/model.ts:30`（`export const HEAT = 'heat'`）、`engine/src/features/curtain/index.ts:126-129`（`k.meters.define({ kind: HEAT, … })`）。文件也還是舊名：dev/adr/0019 第十二節（「場熱是量表 `heat`」）與第十四節（「量表自動有的：`satisfaction`、`heat`」）、dev/work/M4-curtain-run.md:12、dev/work/M4-plan.md:198（給 M5 的對照表 D4）、dev/invariants.md 第 366 條。
- 規格出處：dev/work/M4-plan.md:284「使用者裁決（2026-11-24）……撞名：M4 的場熱量表改名 `stage_heat`，`heat` 留給直播熱度（M5）」；dev/work/M5-plan.md:199-210 第 24 題；dev/adr/0020 D9（「D9 要在 M4 開工前就定」）。
- 會出錯的地方：量表一定義就自動註冊同名的效果與條件（`core/rules/meters.ts` `registerMeterRules`）。M5-live-slot 要註冊效果 `heat`（EVENTS 2.4 節「直播的熱度 ±3」），`EffectRegistry` 遇到已經註冊的種類會丟錯，裝了 `curtain` 的局一開就起不來；反過來先裝 `live` 的話，`curtain` 的量表定義會丟「和已經註冊的效果撞名」。資料（事件、技能）裡寫的 `{ kind: 'heat' }` 也會分不清是哪一個。
- 怎麼修：`HEAT` 改成 `'stage_heat'`（`CURTAIN_HEAT` 這個匯出名可以不動，介面與測試大多經由它）；`engine/data` 的規則與條件、示意包、`ui` 讀量表的地方一起改；ADR 0019 兩處、M4-curtain-run、M4-plan 的 D4、不變式第 366 條改名。補一條測試：同一個 kernel 再註冊一個效果 `heat` 不會撞（模擬 M5）。

### 必修 2：拍賣標到的契約（與機密的效果）交不出去時，照樣扣錢、什麼都沒拿到、也沒有一句話

- 檔案：`engine/src/features/auction/bid.ts:349-352`（`runEffects`：`errors` 不是空的就回傳空的變更與句子；被 `clamp` 整筆拿掉的也是空的，`clamps` 直接丟掉）、`:404-415`（`deliver` 的契約與機密）、`:441`（付款在交貨之前就推進 `changes`）；`engine/src/features/auction/catalog.ts:63-77`（`eligible` 只看有沒有人註冊 `contract_hold`，不看這一件現在交不交得出去）；`engine/src/features/auction/model.ts:259-280`（`lotProblems` 不驗 `contract` 與 `effects` 的內容）。
- 規格出處：LEWD_SYSTEM 6.2「成交：成交價加 10% 佣金……當場取貨……契約的轉讓照第 7 節」；dev/work/M4-plan.md 共同規定第 5 條（不成立丟 `ActionBlocked` 或回傳原因，原因寫成給玩家看的句子）。
- 實際（讀碼確認，三條都會落空）：
  1. 主角已經持有那個人的契約：`contract_hold` 的 `clamp`（`features/contract/effects.ts:185`）回 `effect: null`，`resolve` 沒有錯誤、沒有變更，拍賣把現價加佣金扣掉，結果的句子只有「你付了……」。冒煙的假世界正好是這個組合：`makeHolderGame` 持有阿音（`testkit/scenariosBody.ts:205-209`），目錄裡的 `al_tw_contract` 也是阿音的債（`testkit/worldBody.ts:461`）。
  2. 拍品寫的 `npc` 還不是場上的角色（內容裡有、存檔裡沒有）：同一個 `clamp` 回「找不到這個人，沒有簽成」，一樣落空。
  3. 拍品的 `contract` 參數本身不合格：`M4-auction-bid` 的測試資料就是 `contract: { type: 'debt' }`、沒有 `debt`（`tests/features/M4-auction-bid.test.ts:64`），真的 `contract_hold` 會驗不過（「債務契約要寫 debt」）。測試沒抓到，是因為它換了一個 `validate: () => []` 的假效果（同檔 96-101 行）。
- 怎麼修：(a) `eligible` 對契約與機密先在現在的狀態上試跑一次效果（`k.effects.validate` 加一次不寫入的 `resolve`，有 `clamps` 或錯誤就不抽）；(b) `settle` 先交貨、交不成就不扣錢（這一件改成流標，或讓次高的 NPC 得標），並加一句給玩家看的話；(c) `ready` 時對每一筆拍品的 `contract`、`effects` 跑 `k.effects.validate`，不合格在載入時擋下；(d) `M4-auction-bid` 加一條用真的 `contractFeature` 的測試（已經持有、`debt` 沒寫兩種）。

## 建議

1. **節奏資源的夾法漏了 `quirk` 來源**：`engine/src/core/rules/passive.ts:48`（`TEMPO_SOURCES`）沒有 `quirk`，而怪癖就掛在義體與裝備上（`cyberware/passive.ts:44-56` 以來源 `quirk` 給）。一筆 `{ mod: 'ap_regen', amount: 1 }` 的怪癖會繞過「全身合計最多 +1」（CRAFTING 5.5 節、ITEMS 4.1 節）。加進 `TEMPO_SOURCES`，或在 `passiveContentProblems` 擋怪癖寫正的 `ap_regen`／`ram_regen`。
2. **武器與護甲的怪癖 `effects` 沒有人讀**：`passiveContentProblems`（passive.ts:333-347）收任何怪癖的 `effects`，但只有 `cyberware` 對裝在身上的義體給（`quirkPassives`）；組裝失敗加在槍上的瑕疵若寫成 `effects` 會悄悄不生效（`stats` 有在 `productOf` 算）。在載入時對 `applies` 含 `weapon`／`armor` 而寫了 `effects` 的怪癖給一句警告，或請 `gear` 對穿戴中的成品登記來源 `quirk`。
3. **`action.window` 的骰面**：`lure/window.ts:32` 用 `state.seq.chain` 當鍵，同一條鏈裡每次問結果都一樣（好）；但核心沒有規定回答的人要可重現，建議在 `hooks.ts` 的註解寫明「`replace` 要從狀態導出，不能用 `Math.random`」，免得之後的回答者破壞種子重播。
4. **測試只測到假的接縫**：`tests/features/M4-auction-bid.test.ts:96-101` 的 `contract_hold`、`tests/features/M4-contract.test.ts:873-912` 的收入歸屬都用合成的報告草稿（`work.settle`），沒有一條走真的 `contractFeature` 標拍品、或真的 `work` 打一班。各補一條整合測試（冒煙的 `m4-contract` 可以順手加「契約人打一班」）。

## 要使用者決定的規格問題

1. **（必修 1 的確認）場熱改名 `stage_heat`**：裁決已經有了，只是沒有落實。建議：照裁決改，這一題不必再問，只請使用者知道 M4 收尾修正批要動 `engine/data` 與 `ui` 讀場熱的地方。
2. **契約指令在獨佔的活動裡怎麼辦**（應修 3）：EVENTS 3.4 節只寫了委託副本暫停。潛入、簾後館的一趟、網內的行程、拍賣、成人場景要不要也暫停期限？「照做／抗拒」要不要在這些活動裡也能回？
   建議：兩個都要——`contract.choose` 在任何活動裡都能回（只是回一句話）；期限在玩家處於任何獨佔的活動時都暫停（和委託副本同一個理由：人走不開）。文件代理把 EVENTS 3.4、4.5 節的「在委託副本裡」改成「在任何獨佔的活動裡（委託副本、潛入、簾後館、拍賣、成人場景）」。
3. **`work` 指令怎麼算做完**（建議 5）：LEWD_SYSTEM 7.4 與 EVENTS 4.5 節寫「工作是指定的時段」與「收入大部分歸持約人」，沒寫打完那一班算不算做完。
   建議：在期限內打完一班（`work.` 的結算）就自動做完那一條（滿意 +5、照做次數 +1），抽成只算那一班；之後的班照拿。另一個讀法是維持現狀（要另外走到持約人指定的地方、由事件收尾），但那樣玩家打了工還會被記作廢。
4. **加演的邀請多久有效、要在哪裡接**（應修 1）：CYBERSPACE 8.8 節只寫「到 90 館方開口邀加演」。
   建議：只在結算之後的同一晚、人還站在簾口（簾口在潛入裡時就是潛入中）才接得了；離開、或過了這一晚的時段就作廢，報告一句「館方收回了加演的邀請」。
5. **拍賣標到的東西交不出去時怎麼收場**（必修 2）：LEWD_SYSTEM 6.2 節沒寫。
   建議：不收錢、這一件改由出價第二高的 NPC 得標（沒有就流標），結果寫一句「館方查到這份契約已經轉到你名下／對象不在，這一件撤拍」；目錄抽籤時先排除現在交不出去的拍品，這種情況應該很少發生。
6. **`sink_resist` 的「最少」**：CHARACTER 5.2 節的特質表寫「−1（最少 1）」；QUESTS 與設計書匯出版裡冰后原型寫「每次上升少 1（最少 0）」。引擎照最少 1 做。
   建議：調校的開關一律最少 1（和特質一致）；原型要更強的話，資料多寫一筆抵抗的檢定加值，不另開「最少 0」的開關。文件代理把 QUESTS 的原型那一句改成「最少 1」。
