# W015：跨過一個週一，weekly 觸發點被導演擲了兩次
- 發現者：cpp-tester-whitebox
- 嚴重度：小問題（潛在：現在的資料 `engine/data/rules/event_scopes.json` 沒有範圍聽 `weekly`，所以實際玩不會出現；照 EVENTS 3.3 節把家園的 `weekly` 接上之後就會發生）
- 規格出處：EVENTS 3.1 節（`weekly`：每週一的帳單結算之後——一週一次）、3.3 節（家園：`home`、`rest`、`weekly`）。
- 實際行為：M2 修正批（dev/adr/0017 第 4 點）讓導演的 `turn.end` 收「這一回合提交的每一份報告」的觸發點。帳單的 `time.passed`（順序 10）接著提交的 `bill.settle` 帶 `{ point: 'weekly', where: { overdue } }`，現在也被收進去；而導演自己的 `time.passed`（順序 20）本來就在週一 06:00 擲一次 `weekly`（`where` 是空的）。同一個週一擲兩次：亂數分別是 `director/<週一 06:00>/weekly/<範圍>` 與 `director/<這一回合結束的時間>/weekly/<範圍>`，互相獨立。必中、沒有冷卻的範圍出兩則；真的家園範圍（6 小時冷卻）第一擲沒中時第二擲再給一次機會，機率從 p 變成 1 − (1 − p)²。修正批之前 `turn.end` 只看行動自己那一份，`bill.settle` 的觸發點沒有人讀，所以沒有這個問題（但 `where.overdue` 也從來沒有人收到）。
- 重現：engine/tests/whitebox/fixtures/W015-weekly-rolled-twice.json（城市情境，一個必中的 `weekly` 範圍與一則通知，從星期日 10:00 過到星期一 09:00）。
  會失敗的測試：engine/tests/pending/W014-W015-fix-review.test.ts 的「W015」（拿掉 bills 的對照是一則，會過）。
- 可能的位置（只寫推測，不改）：`features/director/index.ts` 的兩個入口。要定的是哪一個才是「帳單結算之後」那一擲：
  - 留 `bill.settle` 的（帶得到 `overdue`，家園討債的事件要它）：導演的 `time.passed` 有帳單功能時不再自己擲 `weekly`；或
  - 留導演自己的：`turn.end` 收觸發點時略過 `weekly`（或略過由 `time.passed` 接著提交的報告）。
  也可以讓 `runPasses` 認得同一個週一的 `weekly` 只擲一次（記在 state.ext.director）。這是導演的設計，交給 cpp-architect 決定。

- fixed in: 2026-11-23 M2 修 bug 批。選的是「留導演自己的」：`features/director/index.ts` 的 `turn.end` 收觸發點時，這一回合有跨過週一（報告的 `time` 跨過 `weeklyCrossings`）就略過報告帶的 `weekly`（`time.passed` 已經在週一 06:00 擲過）；沒跨過週一、別的功能自己發的 `weekly` 照收。代價：`bill.settle` 帶的 `where.overdue` 還是沒有人收（現在沒有範圍聽它；之後家園的討債事件要它時，要設計成讓導演的 weekly 那一擲向帳單問 `where`，不是兩擲）。回歸測試：`engine/tests/whitebox/W014-W015-fix-review.test.ts`「W015」、`engine/tests/features/M2-fix-bugs.test.ts`「W015」。
