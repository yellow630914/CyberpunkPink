# W014：警戒在開打的那一步跨過 60，壓力條那一擲不見了
- 發現者：cpp-tester-whitebox
- 嚴重度：小問題（副本內事件少擲一次；在現在的資料裡會發生：被保全發現的那一步走進監視器的區塊就 +2，剛好跨過 60）
- 規格出處：EVENTS 3.1 節（`stage`：委託副本的每個階段開始；**壓力條跨過 60**）、3.3 節（委託副本內：壓力條 15%）；`features/commission/run.ts` `pressureDraft` 自己的說明「戰鬥中不發……打完那一份報告再發」。
- 實際行為：
  1. 開打的那一步（`grid.move`，同一份報告裡警戒 +2 跨過 60、開了保全的遭遇）：`report.after` 看到 `state.battle`，不發 pressure（照設計，等打完）。
  2. 打完的 `battle.end`：這一段的目標是打贏（`goal.kind` 預設 `fight`），`achieved` 成立，`report.after` 先回 `milestone`，**不再看 pressure**。
  3. 下一個階段：警戒整趟累計（`run.alert` 70），`chooseBranch` 開地圖時 `start_alert >= pressure_at`，直接記成 `pressured`。
  這一次跨過 60 就一直沒有擲。凡是「讓目標達成的那一份報告」同時讓警戒跨過門檻（打贏的那一場、走到撤離點那一步剛好被監視器拍到），都一樣。
- 重現：engine/tests/whitebox/fixtures/W014-pressure-lost-when-crossing-starts-fight.json（固定種子 5、TEST_WORLD、一個在開打那一步把警戒設成 70 的測試功能）。
  會失敗的測試：engine/tests/pending/W014-W015-fix-review.test.ts 的「W014」。實際的報告：`commission.face commission.branch grid.move battle.start battle.end commission.milestone`。
- 可能的位置（只寫推測，不改）：`features/commission/index.ts` 的 `report.after`：`achieved` 成立時先回 `milestone`，pressure 被跳過。可以在 `milestone` 之前先問 `pressureDraft`（兩份都回，pressure 在前；milestone 之後 `pressured` 會被清掉，所以順序要先 pressure），或在 `milestone` 的草稿上直接帶 pressure 觸發點。要注意導演的 `where` 是這個階段的面（`stageWhere(run, 'meat')`），milestone 之後 run 已經換成下一段。

- fixed in: 2026-11-23 M2 修 bug 批。`features/commission/index.ts` 的 `report.after`：先問 `pressureDraft`，有就只回 `commission.pressure` 那一份（它自己提交之後的 `report.after` 看到目標還是達成，再接 `milestone`；兩份一起回的話，pressure 底下那一輪已經接過 milestone，後面那份會把同一個階段再結算一次、`map.close` 會出錯）。`where` 在 pressure 提交時算（run 還在這一階段）。回歸測試：`engine/tests/whitebox/W014-W015-fix-review.test.ts`「W014」。
