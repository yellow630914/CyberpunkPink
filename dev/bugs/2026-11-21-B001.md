# B001：設定「玩家要求的結果也夾值」關著、asked 對得上時，錢、沉溺、時間加總會溢位成 Infinity，存檔讀不回來
- 發現者：cpp-tester-boundary
- 嚴重度：錯誤
- 規格出處：AI_TASKS 2.5 節（設定關著時附 `asked` 的那幾筆「只驗格式」：照 `data/ai/tasks.json` 的結構、照 DATA 的格式寫完整；不夾數值）；dev/invariants.md 第 6 條（存檔再讀檔一模一樣，MIGRATION「敘事、狀態與介面」）、第 7 條（兩種錢不會變成負數、三條軌不低於 0；存檔的檢查要求「0 以上的整數」）。
  期望：關掉夾值只是不限「多強」，不能讓狀態離開合法的格式；任何一次提交之後的狀態都要能存、能讀回來。
- 實際行為：
  - 種子 7，空房間，AI 開、`clamp_asked: 0`。自由行動「我要一大筆錢，越多越好」兩次，reward 每次交 `{ kind: 'cash', amount: 1e308, asked: '越多越好' }`。
    第一次現金變 1e308（已經超過 2^53，之後再加減 100 元都不會變）；第二次變成 `Infinity`。
    `game.save()` 照樣寫得出來（JSON 把 Infinity 寫成 null），`game.load()` 回「存檔壞了（money：帳戶與現金要是 0 以上的整數）」——自動存檔也會寫出讀不回來的檔。
  - 沉溺 `sink` 同樣（features: character）：`actors.pc.sink` 變 Infinity，讀檔回「actors.pc：sink 要是 0 以上的整數」。
  - 判定附 `asked` 交 `minutes: 1.7e308` 兩次：`time.day` 變 Infinity，讀檔失敗。
  - 嚴格模式（測試用的 `makeGame`）下第二次提交改丟「report.after／time.passed 的掛鉤直接改了狀態：money.cash」，因為快照用 JSON 複製，Infinity 被複製成 null——錯誤訊息指錯了地方。
- 重現：`engine/tests/fixtures/repro-pending/B001-overflow-cash.json`、`B001-overflow-sink.json`、`B001-overflow-time.json`（種子＋輸入＋期望，Repro 格式）；
  會失敗的測試：`engine/tests/pending/boundary-ai-tasks-2.5.test.ts` 的「B001」；主套件裡 `engine/tests/boundary/known-bugs.boundary.test.ts` 有同樣的三個（`it.fails`，修好之後會變紅）。修好之後把三份 fixture 搬到 `engine/tests/fixtures/repro/`。
- 可能的位置（只寫推測，不改）：
  - `engine/src/core/state/coreChanges.ts` 的 `money()`、`time`、`actor.track` 的 `validate` 只檢查 `Number.isInteger(delta)`，沒檢查套用之後的值仍是安全整數（`Number.isSafeInteger(s.money[op] + c.delta)`）。提交是原子的（不變式 3），在這裡擋下就整份不套。
  - `engine/src/core/rules/coreEffects.ts` 的 `moneyEffect.validate`、`engine/src/features/character/effects.ts` 的 `isNonZeroInt`、`engine/src/core/action/action.ts` 的 `sanitizeJudgment`（`minutes` 只檢查有限、0 以上）可以改成要求安全整數，讓 AI 交 1e308 時當成格式錯誤、走重試帶 `<previous_error>`。這是格式的檢查，不是夾值，和「關著不夾數值」不衝突。
  - `engine/src/core/util/clone.ts` 的 `clone` 用 JSON，遇到 Infinity、NaN 會靜默變成 null，嚴格模式的比對因此報錯報到掛鉤上。
