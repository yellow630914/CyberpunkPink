# 0012 格子地圖的引擎：模型、實例、站上一格會發生什麼

- 日期：2026-11-22　狀態：採用（M1 開工；MIGRATION E 的 `grid`、`specialMaps`）

## 背景
委託副本的現實面（COMMISSION_MAPS、SITES 12.5 節）與內海的子網都是「一張格子圖，人在上面走，走到東西就發生事」。Demo 有兩份（`ui/src/lib/grid.ts`、`dungeon.ts`），規則在介面裡。M1 要的是：委託地圖的格式讀得進來、走得動、走到敵人那一格就開打；副本本身（警戒、巡邏、門鎖、目標）在 M2，子網在 M3。

## 選項
1. 地圖做成一個功能，委託副本與子網各自 import 它。違反「功能之間不直接 import」。
2. 核心只放型別，走路的規則各功能自己寫。會寫出兩三份尋路與視野。
3. 核心有模型、實例、走一步的規則與一張登錄表；站上一個標記會發生什麼由功能註冊。

## 決定
採用 3（`engine/src/core/grid/`，L5）。

- **定義**（內容種類 `special_map`，DATA 9.3 節的格式）：一個模板一筆，裡面一到幾張圖；每張圖有版面（一列一個字串）、圖例、區塊、標記（入口、撤離點、目標、保全崗……）、遭遇點（用哪種遮蔽的配置與場地效果）、控制面板、連到別張圖的格子、巡邏路線。載入時檢查：列數與每列的長度、只有圖例裡的字元、標記和版面對得上、每一格從某個入口走得到、每張至少兩個遭遇點。
- **模型**（`Sheet`）：這一格是什麼、能不能走、在哪個區塊、上面有什麼標記；最短路（四方向）；從入口走得到的範圍；視野。
- **實例**（`state.maps`）：一份定義可以開很多份實例（一件委託一份）。實例只記會變的東西：看過的格子、改過的格子（門開了、標記用過了）、會動的東西在哪、發起的功能自己的資料（`ext`）。現在站在哪一份、哪一張、哪一格記在 `state.maps.at`。只經由 `map.open`、`map.close`、`map.at`、`map.sheet`、`map.ext` 這幾種變更改變。
- **走一步**（`gridWalk`）：一個方向，或一個目的地（照最短路走，遇到事情就停）。牆與擺設擋路；要條件的格子（上鎖的門）問登錄表的放行規則，沒有人註冊就過不去。每走進一格更新看過的範圍。
- **登錄表**（`k.grid`）：站上帶某種標記的格子（`onMark`）、每走進一格（`onEnter`：監視器、巡邏、陷阱）、某種格子過不過得去（`passRule`）、這一格現在能做的事（`usesOf`：畫面走到上面立刻列出來）。處理函式回傳「加進這一步的變更」「接著要提交的報告」「在這一格開打（一份開戰的設定）」「到這一格為止」。
- **走到敵人那一格就開打**：處理函式回傳開戰的設定，外殼提交完這一步之後照它開戰。用哪個遭遇點（那一區的、走路最近的）由探索的功能決定，引擎不寫死。
- 在地圖上走不花遊戲時間（一步一步算時間是 M2 的事，見 0013）；走路併進最新一樓，不另留回退。

## 後果
- 委託地圖（COMMISSION_MAPS 的三十個模板）與子網用同一套格式與同一個引擎；M2、M3 要做的是註冊各自的標記與規則。
- DATA 9.3 節的小辦公室樣本載得進來，但有一處內容的問題：接待區通往開放座位的門正對著一個擺設，照「擺設擋路」走不過去（開放座位只能從二樓的窗進）。格式檢查不擋這種事（每一格都從某個入口走得到）；已經回報。
- 視野、巡邏的移動、警戒只有資料的欄位與登錄表的掛點，規則在 M2。
- Demo 的 `ui/src/lib/grid.ts` 與 `dungeon.ts` 在介面換成引擎之後才刪（M2）。
