# 0008 整個回合是一件事；重試只限最新一樓；行動的三種結果；回到快照

- 日期：2026-11-22　狀態：採用（審查 E2、E4；bug B003、B004、B005、W001、W002、W003、W007、W009；介面回報的「併進最新一樓」與「回退但保留報告」）

## 背景
M0 的門面（`Game`）有幾個地方把「不成立的動作」和「成立的動作」的邊界畫錯：
掛鉤接著提交的報告不合法時，原本那份已經套用，呼叫的人卻收到錯誤（W001）；不合法的重試請求先回退了最新一樓才被拒絕（B005）；
已經套用的鏈之後又有別的提交，再重試會把之後的提交一起抹掉（E2）；堆疊滿了時，一個失敗的動作會擠掉最舊的一步（B003、W007）；
讀檔修復失敗時狀態已經換掉（W003）；介面把「行動被擋下」和「鏈停下來等玩家」當成同一個 `blocked`（E4）。

## 決定

### 1. 整串報告是一件事（W001、W002）
兩個做法：(a) 原本那份與掛鉤接著提交的全部在同一份複製的狀態上套完才換進去；(b) 原本那份照常提交，接著的另外處理（記成待辦、轉成債）。
**採用 (a)。** 提交是原子的這一條不該有「一半」：接著的報告不合法是功能的 bug（例：帳單要自己處理付不出來的情況），這時整個回合不算，狀態完全不變。
- `commitAtomic(k, state, fn)` 是共用的入口；`commitTurn` 的 `turn.end`、`Game.newGame` 的開局、讀檔修復都走它或同樣的做法。
- 掛鉤拿到的 `state` 是這次提交的工作副本。嚴格模式連 `turn.end` 一起查。
- 探針的事件整串成功才送出：沒有換進去的報告不會出現在觀察的紀錄裡。
- 代價：一個壞掉的掛鉤會讓它掛的那種動作全部失敗。這比留下一半的狀態好查。

### 2. 重試只限最新一樓，而且之後不能有別的提交（E2、B005）
- 重試、重擲、用規則代替都先問 `requestBlock`（純粹的檢查）；不成立就丟錯，狀態與鏈都不動。成立了才回退這一次套用。
- 鏈套用完記下報告的流水號；之後流水號變了（任何一份別的提交），這條鏈就只能回退。任務鏈列還看得到它，`Game.stepActions(stepId)` 回報三個按鈕各自能不能按與原因，畫面照這個顯示。
- 考慮過「之後的提交一律讓最新的鏈消失」：做法更短，但任務鏈列會在玩家買一瓶水之後整個不見。
- 鏈停在半路時提交別的報告：那條鏈作廢（和開始新的行動一樣）。鏈還在跑時不能提交（丟錯）。

### 3. 提交可以併進最新一樓（`commit(draft, { attach: true })`）
AI_TASKS 5.5 節：沒有正文的鏈算在當時最新的那一樓。買東西的帳、坐車的時間用 `attach`，不另留一步回退；回退一步時連同它前面那一步一起收回。
回退的堆疊另外修兩件事：失敗的動作不改能回退的步數（被擠掉的那一步會放回去；程式結算的提交改成成立之後才記）；步數不是正整數回 false。

### 4. 行動的三種結果用三個字（E4）
`Game.act` 的 `status`：`applied`（套用了）、`paused`（鏈停下來等玩家重試、重擲或改用規則；狀態還沒改）、`refused`（行動被擋下，附 `reason`；狀態不變、不留回退、沒有鏈可以重試）、`cancelled`。
- 原本鏈的狀態叫 `blocked`，介面替被擋下的行動也取了 `blocked`。兩邊都改名，`blocked` 這個字不再當狀態用：留著任何一邊，舊的程式碼比對 `'blocked'` 時都還是會有一半的機會比到錯的意思。
- 引擎裡「block」這個字只剩「擋下，附原因」的意思（`ActionBlocked`、`attrBlock`、`CreationBlock`、`requestBlock`）。
- 被擋下的行動不再丟錯。程式的錯誤（沒有這種行動）照樣丟。

### 5. 回到快照但保留紀錄（`Game.rewind`；SERIES 第 6 節）
撤退與戰敗後的回退要把進度回到快照，但紀錄、性經歷、記憶留著。
- 快照就是 `save()` 的文字（介面本來就這樣記；它要跟著存檔走）。`rewind(raw, { summary })` 驗過之後：狀態回到那一刻（亂數的位置也回去）；之後的報告留在紀錄裡並標 `retracted`；最後提交一份報告，`summary` 是交代這件事的那一段敘述。
- 功能要保留自己那一塊，掛 `rewind.keep` 回傳變更（性經歷、共同記憶在 M2 註冊）。核心不認得那些欄位。
- **流水號接著往下走**，不回到快照的值：報告與鏈的編號不能重複。副作用是擲骰的用途裡有鏈的流水號，所以撤退之後再做同樣的事，骰子不保證和上一次一樣。一般的回退（`undoSteps`）不受影響，仍然擲出同樣的骰。這一點規格沒有寫（「沿用回退機制」），已回報。
- 之後不能回退到這之前（回退的堆疊清空），和讀檔一樣。

### 6. 讀檔與開新局先在旁邊做完（W003、審查 S11）
讀檔修復在讀進來的那一份上做，成功才換進來；失敗回傳錯誤訊息，狀態、回退、進行中的鏈都不變。
`newGame` 多一個 `setup`（開局接著要提交的報告，例如建角）：任何一步丟錯，原本那一局完全不動。

## 後果
- 介面要改的地方寫在 dev/work/M0-fix-ui.md。
- `time.passed` 這類掛鉤回傳的報告一定要合法；會付錢的掛鉤（M2 的帳單）要自己看錢夠不夠。
- 委託副本的快照（每個階段、每場戰鬥）由委託的功能在 M2 管；引擎只提供 `rewind`。
