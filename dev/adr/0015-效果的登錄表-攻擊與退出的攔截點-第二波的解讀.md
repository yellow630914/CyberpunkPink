# 0015 效果是一張登錄表；攻擊與退出的攔截點；和人重疊的東西自己動；義體在戰鬥裡的樣子；M1 第二波的解讀

- 日期：2026-11-22　狀態：設計（M1 第二波；核心的部分由兩張小工單實作：dev/work/M1b-core-effects.md、M1b-core-overlay.md；第四節的解讀與暫定值等使用者看）
- 延續 0010（行動與修正是登錄表）、0013（解讀與暫定值）、0014（行動的宣告）。

## 背景

第二波要做的機制：其餘六棵技能樹的現實面、槍手與掮客還標 `pending` 的技能、敵人的招牌行動、敵方的無人機與砲塔、投擲物、腳本、特殊彈、名冊轉不進格式的欄位（燃燒、義體失效、沉溺、特徵）。逐條對過之後，它們要的東西九成是同一批「效果」（打一下、灌感載、回生命、給狀態、推拉、動遮蔽、動行動點、讓義體失效……），只是從不同的地方觸發：道具、技能、招牌行動、武器命中、快駭。現在只有道具走登錄表（`k.battle.itemOp`），技能的效果寫死在 `features/abilities` 的一張封閉的鍵表裡；照這個寫法每多一個來源就要在那個功能裡重寫一次同樣的效果，而且機師的技能要叫無人機做事（`features/summons`）、改造師要叫快取格的道具做事（`features/combat`），功能之間不能互相 import。

另外有五件事現在的核心做不到：攻擊被改打到別的東西上（無人機擋槍、立牌、替身）；人「即將倒下、即將被制伏」時被救下來，以及倒下的人回到場上；沒有操作者的無人機與砲塔自己開火；「讓一件義體失效」（技能、電磁彈、電磁手雷、快駭、干擾型無人機、敵人的武器都要用）；每一輪開頭的掛點。

## 選項

1. 每個功能自己加鍵、自己寫效果。最快，但同一個效果寫四五份，機師與改造師的技能做不出來（要 import 別的功能）。
2. 把所有效果搬進核心。核心變成內容的解譯器，違反 0010「核心只有機制」。
3. **效果是登錄表**：核心只有「登錄、解析對誰、照順序做、帶著上一筆的結果」；每個效果由管那個領域的功能註冊；道具、技能、招牌行動、武器的附帶效果、快駭都只寫 `[{ op, ... }]`。

## 決定

採用 3。

### 一、效果的登錄表（核心工單 M1b-core-effects）

- `k.battle.effect(op, owner, fn)` 取代 `k.battle.itemOp`（舊名留成別名，道具照舊）。
- 處理函式拿到 `(ctx, e)`：
  - `ctx`：`run`、`user`（做的人）、`target`（玩家選的目標，可以是人、一格、一台、沒有）、`unit`（這一筆落在誰身上）、`overlay`（落在哪一台上；範圍打到掛著的東西時）、`source`（`{ kind: 'item' | 'ability' | 'weapon' | 'hack' | 'field', id, name }`）、`pick`（這一步其他的選擇）、`n`（公式要代的數字：`tier` 樹階、`grade` 場景等級、`spent` 花掉的格數或 RAM）、`last`（上一筆攻擊或檢定的結果：`hit`、`crit`、`downed`、`ok`、`dealt`）。
  - `e`：資料裡的那一筆。
- `run.effects(list, ctx)` 照順序做。每一筆可以帶兩個共同的欄位，由核心解析：
  - `who`：這一筆落在誰身上。封閉清單：`target`（預設）、`self`、`allies`（我方在場的每個人）、`others`（扣掉自己）、`adjacent`（和做的人站位差 1 的隊友）、`near`（自己加相鄰）、`foes`、`foes_bridged`（敵方有橋的人）、`slot`（目標那一格上的人）、`area`（目標那一格加 `pick.also` 那一格上的每個人與掛著的每一台）、`attacker`／`victim`（反應裡：正在攻擊的人、被打的人）、`pick:<鍵>`（`pick` 裡那個單位）。一筆落在好幾個人身上就各呼叫一次。
  - `if`：`hit`、`miss`、`crit`、`downed`、`overloaded`、`ok`、`fail`（看 `ctx.last`），`first_round`、`not_first_round`；不成立就跳過這一筆。
- **數量可以寫公式**（字串，封閉的文法）：用 `+` 接起來的項，每一項是整數、`NdM`、`tier`、`half_tier_up`、`half_tier_down`、`grade`、`spent`、`skill:<基本功>`、`mod:<屬性>`，項可以再 `*整數`；骰數也可以是名字（`spentd6`：花掉幾點就擲幾顆）。核心給 `amount(ctx, expr)` 與載入時用的 `amountProblems(expr)`。
- 內容載入時，每個來源（道具、技能、招牌行動、武器的附帶效果、快駭程式）用到的 `op` 都要查得到，查不到就擋下、訊息裡寫出那個 `op`。
- 誰註冊什麼：`features/combat` 註冊通用的（攻擊、傷害、感載、回復、狀態、推拉、遮蔽、行動點、彈匣、義體、救回來、重創、退出、場地；dev/work/M1b-ops.md）；`features/summons` 註冊無人機的；`features/abilities` 註冊 `buff`；`features/hack` 註冊快駭的。

### 二、攻擊的攔截點（M1b-core-effects）

- `AttackOpts` 多三個欄位：`natural`（用已經擲好的骰面：投擲物一顆骰對兩格）、`armorMult`（目標的護甲乘幾倍：空尖彈 2）、`redirect: { overlay }`（由 `attack.before` 的處理函式設：這一擊改打那一台，照它的迴避與護甲算，原本的目標不受影響；第一個設的算數；結果帶 `redirected: true`）。
- 新掛點 **`attack.hit`**：命中已經確定、傷害還沒算。帶 `roll: { natural, total, evade, crit, wound }` 與 `out: { negate?, wound? }`。處理函式把 `out.negate` 設成 `true`：這一擊不造成傷害、不重創、不推拉（遮蔽照樣受傷）；`out.wound = false`：重創改成一般的命中。
- 新掛點 **`out.before`**：有人即將退出（倒下、昏過去、被制伏）。帶 `how` 與 `out: { prevent? }`。被擋下時 `setOut` 回傳 `false`、什麼都不做；因為生命歸零而來的，核心保證擋下之後生命至少 1，其餘的數字由處理函式自己改。
- 新的基本動作 **`run.revive(unit, hp)`**：只收因生命歸零倒下的人（`out === 'down'`）。回到場上：有空格放最後面的空格（和增援同一條，0013 C6），沒有就排進後方的最前面；行動點 0、狀態清空、先攻的順位不變；事件 `revive`。
- `run.heal`、`run.vent` 多帶「誰做的」與標籤；新的修正 `heal_dealt`、`vent_dealt`（做的人造成的回復多幾點）。
- `run.save` 多帶標籤與「對誰擲的」（`other`），修正讀得到；帶著 `other` 的檢定在擲之前發新掛點 **`check.before`**（`{ run, unit, other, tags, opts: { dc, bonus } }`：被快駭、被誘惑的那一方的反應在這裡改 DC）。新的修正 `firewall`（目標的防火牆加減，問的是目標）。現有的呼叫補上：制伏 `subdue`、抵抗壓制 `resist:suppressed`、士氣 `morale`、脫離 `flee`。
- 新的修正 `ai_target_pct`：AI 挑目標時候選人的權重加減幾個百分點（−100 就是不挑他；每個候選都是 0 時當成沒有這個修正，也就是「除非他是唯一打得到的目標」）。新的修正 `see_dark`：大於 0 的人攻擊時不吃黑暗（和 `night_vision` 標籤並存）。
- 花費：行動可以照這一步的輸入多給幾個標籤（`costTags`：用的是哪一類道具、是不是治療），減免才認得出「用醫療道具」；新的修正 `action_ram`（行動花的 RAM 加減，最少 1）。新的修正 `wound_grade`（重創的級數加減：−1 是重的改成輕的；`features/combat` 擲部位時問）。
- 先攻：`run.swapOrder(a, b)` 對調兩個人的順位；`run.actNext(u)` 把這一輪還沒動過的人排到現在輪到的人後面一位（已經動過的回傳 `false`）。

### 三、和人重疊的東西、義體、回合（M1b-core-overlay）

- 新掛點 **`round.start`**（每一輪開頭；第一輪也發）。
- `BattleOverlay`：`owner` 可以沒有（裝在場景上的、巡邏用的）；多 `weapon`（它自己的武器）、`auto`（每一輪自己做一個動作）、`autonomous`（操作者退出時不停機：改成沒有操作者、`auto` 開著、`ext.orphan = true`）。操作者退出時停不停機由放它的功能決定，核心不再一律停機（見 E6）。
- `run.addOverlay(init)`：發 id、查每格一台、有操作者時耐久、護甲、迴避各問一次修正（`overlay_hp`、`overlay_armor`、`overlay_evade`，標籤是它的種類）。同時連得住幾台的加減是修正 `overlay_cap`，自己的一台被擊落時操作者受的感載加減是 `overlay_backlash`（都由 `features/summons` 問）。`features/summons` 改用它。
- `run.overlayAttack(o, target, opts)`：這一台自己開火。攻擊者是核心臨時組的**替身**（不在 `battle.units` 裡；名字、哪一方、哪一格照這一台；傷害倍率照 `o.ext.dmgMult`；標籤 `machine`、`overlay`；`ext.overlay` 是這一台的 id）。`run.attack` 的目標是替身時自動改走 `attackOverlay`，所以反應打回去不必自己分；狀態給不到替身身上。`attackOverlay` 也發 `attack.after`（目標是替身）。
- **義體**：`BattleUnit.implants`（開打時的快照，每一件 `{ kind, name, contract? }`）；`cyber` 沒寫時就是件數。來源：敵人資料的 `cyber`、角色的由 M4 的義體功能經 `loadout` 給（在那之前主角這一邊是空的）。
- **失效與超頻是狀態**：`run.implantStatus(target, 'off' | 'boost', { kind?, pick?, by?, turns?, until? })` 挑一件（指定的索引 → 指定的種類 → 第一件還沒帶這個狀態的），給狀態 `off_<kind>` 或 `boost_<kind>`（查不到用 `off_generic`、`boost_generic`）；沒有可挑的回傳 `null`。每一種義體失效或超頻時差多少是規則表的資料（`battle_status`；dev/work/M1b-data-rules.md），核心不寫數字。

## 後果

- 技能、道具、招牌行動、武器的附帶效果、快駭用同一套效果與同一套公式；之後內海（M3）的構裝、藥（M4）只要註冊自己的 `op`。
- `features/abilities` 現有的鍵（`attack`、`apply`、`free_move`……）留著，新的技能一律寫 `do`（dev/work/M1b-skill-format.md）；兩種寫法並存到正式內容匯入時統一。
- 核心多了替身這個概念（不在單位清單裡的攻擊者）。凡是拿到 `attacker` 的掛點都可能拿到替身；要對攻擊者做攻擊以外的事（給狀態、推拉）的功能要先看 `ext.overlay`。
- 效果的 `who` 與 `if` 是封閉清單；不夠用時加在核心，不在功能裡各自解析。
- 第四節每一項被否決時要改的地方都只在一張工單的範圍裡；E6 是設計書的矛盾，要使用者裁決之後改設計書。

## 實作補記（M1b-core-effects，2026-11-22）

- 型別改名避開報告效果系統：`BattleEffectCtx`、`BattleEffectSource`、`BattleEffectDef`、`BattleEffectInput`、`BattleEffectLast`、`BattleEffectNumbers`、`BattleEffectOpts`；`BattleEffectOp` 照原名。
- 補的欄位：`ctx.last.stop`（停止後面的效果）、輸入與 ctx 的 `attacker`／`victim`、`last.overloaded`。redirect 不發 `attack.after`；生命歸零被擋下時拉回 1。

## 實作補記（M1b-core-overlay，2026-11-22）

- 型別：`BattleImplant`、`BattleOverlayInit`（`run.addOverlay` 收的，不含 `id`、`used`、`down`）、`ImplantStatusOpts`；`Loadout.implants`；`BattleOverlay.ext.dmgMult` 是 `{ hp, load }`（寫一個數字就是生命的倍率，沒寫都是 1）。`round.start` 掛點的 payload 是 `{ run, round }`。
- `round.start`：第一輪由 `setupBattle` 發（在 `battle.start` 與「第 1 回合」那一拍之後、第一個人的 `turn.start` 之前），之後每一輪由 `endRound` 發；處理函式做完核心呼叫 `run.settle()`（補位、看結果），掛點裡分出結果就不再輪到下一個人。
- `addOverlay(init, { text? })`：預設的那一拍，有操作者是「某某 放出{名字}，掛在第 N 格。」（無人機現有的句子，資料鍵 `{ overlay, kind, slot }`），沒有是「{名字}掛在{我方／敵方}第 N 格。」；`weapon` 與 `ext` 複製一份；耐久最少 1、護甲最少 0。連得住幾台（`overlay_cap`）由放它的功能先查，`addOverlay` 只管每格一台。
- 替身（`run.standIn(o)`、`run.isStandIn(u)`、`run.overlayOfStandIn(u)`）沒有 `hp` 與 `load`，所以回復、感載、傷害對它都沒有效果；`setOut` 也不動它。`run.attack` 的目標是替身而那一台已經被擊落或不在了，回傳 `aborted`（不會當成打人）。`attackOverlay` 拆成兩層：對外的發 `attack.after`，`redirect` 走的內層不發（維持 M1b-core-effects 的「redirect 不發 attack.after」）。
- 自律：`orphan` 留一拍（標籤 `overlay`，資料 `orphan: true`），不發 `overlay.down`。`features/summons` 自己放的無人機這一張沒有標 `autonomous`（工單要求照舊停機、`M1-summons` 的測試要照樣過），所以「我方的也自律」還沒生效：要生效時，放出的時候帶 `autonomous: true`、在 `round.start` 照 `ext.orphan` 做命中 −2 與不移動、把 `tests/features/M1-summons*.test.ts` 兩處「所有無人機停機」改成自律（M1b-enemy-units 動 `features/summons` 時一起做）。
- `implantStatus`：回傳挑到的那一件（就是 `target.implants` 裡的物件）。「還沒帶這個狀態」看狀態 id：同一種的兩件、或規則表都沒有、同樣退回 `_generic` 的兩件共用一個狀態，第二次就沒有可挑的（要換掉第一件的時間用 `pick`）。記的那一拍是 `status`（資料 `{ target, status, implant, mode }`），取代狀態自己的那一拍（`StatusOpts.quiet`）。
- 沒做的（ADR 沒寫、工單也沒要）：沒有操作者的一台的 `used` 沒有人會在回合開始時清（`turn.ts` 只清自己操作者的），要不要每輪清由 `round.start` 的處理函式決定；`BattleImplant` 沒有「被拆下」的欄位（M1b-skill-medic 的 `implants[i].gone` 要先補進型別）。

## 實作補記（M1b-core-closeout，2026-11-22）

- **改打結算之後發新掛點 `attack.redirected`，不讓它發 `attack.after`**：`attack.after` 的處理函式（武器的命中效果、反應）都假設 `target` 是被打中的人，改打時那是錯的；新掛點帶原本的目標、吃下這一擊的那一台與它的結果，立牌「吃下一擊就倒下」放在這裡（打中、打空、被護甲擋光都倒）。
- **取消一擊**：`attack.before` 的處理函式設 `opts.cancel`（一句話），核心結束這一擊（不擲骰、不發 `attack.after`、記一拍、`aborted` 且帶 `cancelled`、後面的處理函式不再跑），記完發 `attack.cancel` 放後果（炸膛傷到自己，順序才是「炸膛」在前、受傷在後）。彈匣扣在 `attack.before` 之前，所以卡彈照樣花彈匣；卡彈與炸膛因此從行動移進 `features/combat` 的 `attack.before`（排在最前面），技能效果的 `{ op: 'attack' }`、反應、打掛著的東西都吃得到。
- `attackOverlay` 也發 `attack.before`（`target` 是替身，不看 `redirect`）。`run.damageOverlay(o, raw, type, by, { pierce, armorMult })` 是掛著的東西的直接傷害的唯一算法。
- **沉溺**：傷害類型自己帶的沉溺走 `run.gainSink`（`sink.before` 擋得下）；呼叫的人的效果自己決定的用 `AttackOpts.noSink`（on_hit 帶定力檢定的 `sink`），不再先加再扣。
- `StatusUntil` 加 `next_overload`（`BattleUntil` 的 `{ at: 'overload' }`）；物品的 `use.range: [近, 遠]` 只給 `use.target: foe`；`features/combat` 的 fx 合併 `armor_mult` 改相乘。行動灰掉的「不夠」那一句用資源池的中文名（`POOL_NAMES`）。
