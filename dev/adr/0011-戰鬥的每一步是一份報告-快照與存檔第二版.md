# 0011 戰鬥的每一步是一份報告；骰子是導出來的；快照放在狀態裡；存檔第 2 版

- 日期：2026-11-22　狀態：採用（M1 開工；延續 0003、0005、0008）

## 背景
M0 定了「狀態只經由提交報告改變」「每個動作一份報告」「骰子由種子與游標導出」「回退最多五步」。戰鬥是幾十步的互動，Demo 的做法是整場戰鬥放在畫面的記憶體裡，打完才把結果寫回去：存不了檔、重新整理就沒了、回退與探針看不到、種子重播重不了。
另外 COMBAT_SYSTEM 8.4 節要「重來這場戰鬥」「回到這個階段開始時」，SERIES 第 6 節要撤退回到進副本之前：都要有地方放那一刻的狀態，而且要跟著存檔走。

## 選項
- 戰鬥狀態放哪：(a) 外殼的記憶體，打完交一份報告；(b) 放進遊戲狀態，每一步一份報告。
- 骰子：(a) 戰鬥自己帶一個會往前走的亂數狀態；(b) 照 0003 導出，用途裡帶著「這一場的 id 與這一場擲到第幾次」。
- 回退：(a) 戰鬥的每一步都能回退；(b) 開戰留一步，戰鬥裡的每一步併在同一樓。
- 快照：(a) 外殼自己留著、不進存檔；(b) 放進狀態。

## 決定
- **戰鬥狀態是遊戲狀態的一部分**（`state.battle`，沒有在打是 `null`）。只有 `battle` 這一種變更能改它。開打、玩家的一步、AI 的一步、結束各是一份報告（`battle.start`、`battle.step`、`battle.end`），照常經過提交、不變式檢查、探針。
  - 每一步的做法：複製戰鬥狀態 → 在副本上算（`BattleRun`）→ 產生一份報告草稿，裡面一筆 `{ op: 'battle', state: 新的狀態, step: true }` 與這一步的紀錄（一拍一句）。做不成的一步丟 `BattleBlocked`（帶每一條原因），副本丟掉，狀態不變。
  - 變更記進紀錄時不留整份戰鬥狀態（只留 id 與回合），不然紀錄會膨脹。
  - **結束時收成一份**：`battle.end` 的報告帶著這一場每一步的紀錄（太長時保留頭 60 拍、尾 140 拍）、三條軌寫回角色的變更、功能加進來的變更；`{ op: 'battle', state: null, fold: true }` 把這一場每一步的報告從紀錄裡拿掉。紀錄裡一場戰鬥只有一筆。
  - 戰鬥中每一步不算一個「回合」（不跑 `turn.end`），結束那一份才算；戰鬥中不能跑別的任務鏈。
- **骰子照 0003 導出**：用途是 `battle/<這一場的 id>/<這一場擲到第幾次>`，次數記在戰鬥狀態裡。同一個狀態、同一串輸入，整場一樣；存讀檔不影響；結束時遊戲的游標往前一格。戰鬥裡沒有「重擲」。
- **回退**：開戰留一步；戰鬥裡的每一步併進那一樓、不另留。戰鬥中按回退就是回到開打之前（骰子不換，照 GAME_DESIGN 第 9 節）。五步的額度不會被一場戰鬥吃光。
- **快照放在狀態裡**（`state.snapshots`：id、種類、標籤、那一刻的存檔文字、附帶的資料）。快照裡不再包快照。`Game.rewindTo(id)` 回到那一刻但保留之後的紀錄（照 0008 的 `rewind`），比它晚的快照與它自己一起丟掉。
  - 每場戰鬥開打前自動留一份（種類 `battle`，附著開打的設定；同一時間只留最新的一份）。`Game.retryBattle()`：回到那一份、照同一份設定再開打。骰子不保證和上一次一樣（SERIES 第 6 節的定案）。
  - 「回到這個階段開始時」與撤退用同一個機制，快照由委託副本的功能在 M2 存（種類 `stage`、`entry`）。
- **存檔第 2 版**：`GameState` 多了 `battle`、`maps`、`snapshots`，存檔規則多了敵人的係數（BALANCE 7.2 節）、戰敗扣錢的金額上限、重創要不要留傷勢。第 1 版的存檔照遷移的掛點升上來（`engine/tests/fixtures/saves/v1-m0.json` 是回歸用的舊檔）；第 1 版把「戰敗最多扣多少錢」預設寫成 0（當時沒有地方用它），升級時照 COMBAT_SYSTEM 8.3 節改成 1。

## 後果
- 戰鬥打到一半可以存檔、讀檔、重新整理，接著打的結果和沒有中斷的一樣；種子重播與探針看得到每一步。
- 每一步都複製一次戰鬥狀態並提交一份報告：一步約 5～7 毫秒（四對四），玩家感覺不到；整場自動打完約 0.3 秒，平衡模擬要跑幾千場時直接用核心的函式（不經過 `Game`）。
- 快照是整份存檔的文字，一份幾十 KB；同時留著的不會多（戰鬥一份，副本的階段與入口各一份）。存檔因此變大，匯出時一起帶著。
- 戰鬥中不能回退到「上一步」。這是刻意的：戰鬥裡的每一步都擲過骰，能一步一步回退等於能挑骰。要重來只有整場重來。
- 畫面上一場戰鬥的紀錄在打的時候是一步一筆，結束後變成一筆；介面照 `state.reports` 顯示就好。
