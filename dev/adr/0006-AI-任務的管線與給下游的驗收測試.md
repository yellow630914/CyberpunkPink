# 0006 AI 任務的管線、假的服務商，以及給下游的驗收測試怎麼放

- 日期：2026-11-21　狀態：採用

## 背景
AI 呼叫從一開始就照任務拆開（AI_TASKS），M0 先接假的服務商。工單要附「已經寫好、目前會失敗」的驗收測試，但主套件要保持綠色。

## 決定
1. **一個任務＝四個函式**：`build`（組請求：固定前段加一段一段的 `<標籤>`）、`check`（驗證與夾值）、`fallback`（不用 AI 的退路）、加上 `onExhausted`（自動重試都失敗之後等玩家還是走退路）。`runTask` 是所有任務共用的：排隊（同時最多 3 個）、閒置逾時 3 分鐘、取消、解析、錯誤分類、自動重試時把錯誤放進 `<previous_error>`。它不丟錯，結果是 `done`、`fallback`、`failed` 三種。
2. **一條鏈＝模板加四組函式**：模板是 AI_TASKS 2.7 節那份 JSON 原樣（`steps`、`needs`、`when`、`branch`）；另外給程式步驟的實作、`when` 的條件、每個 AI 步驟的輸入怎麼組、最後怎麼把草稿變成報告。套用之前所有的結果只在草稿裡。
3. **夾值在任務的 `check` 裡**，所以寫正文拿到的 `<results>` 一定是夾過的；寫正文的 `check` 只做文字的檢查與 `<covered>` 的對照，不交出任何數值。
4. **請求裡有一段機器讀的 `<input>`（JSON）**。提示詞的文字之後從 PROMPTS 轉成資料；假的服務商與測試只靠 `<input>`，換提示詞不會弄壞測試。
5. **假的服務商在 `shell/ai/`，不在 testkit**：介面在沒有金鑰時也接它。它有劇本、自動（照 `<input>` 回合格的回應）與十種對抗模式。
6. **設定的形狀沿用 `cpp-ai-v1`**（設計書示意頁用的那一份，鍵是 `clamp_asked`、`judge_free`……，開關存 0／1）。引擎只收物件。介面目前存的是另一個鍵與駝峰式的欄位，由介面那邊轉（M0-ui-engine）。
7. **服務商怎麼選**：總開關關著 → 沒有（走退路）；任務指到的來源有金鑰、而且那一家已經註冊 → 真的；否則 → 假的（有給的話）。M0 沒有任何一家真的服務商註冊。
8. **給下游的驗收測試放 `engine/tests/pending/`**（介面的放 `ui/tests/pending/`），主套件不跑它、型別檢查也不看它；用 `npm run test:pending` 跑。它們直接 import 還不存在的模組，所以現在整個檔失敗。工單完成後把檔案搬到 `tests/features/`（或 `tests/data/`、`tests/smoke/`），就進了主套件與型別檢查。寫的時候用暫時的型別宣告檢查過一次，照工單的函式簽名做就過得了型別檢查。

## 後果
- `relate`、`flavor_roster` 兩個任務還沒有（NPC 與名冊在 M2）；模板裡那兩步的 `when` 現在一定不成立，所以被略過。
- Agent 模式的掛點、工具調用、多輪對話只有型別，沒有實作。
- 寫正文的硬規則目前只檢查「不是空的」與 H10（不寫標題）；H4（數字不寫進文字）等提示詞搬進來時再補，因為直接擋數字會誤傷地名（四十二番街）。
