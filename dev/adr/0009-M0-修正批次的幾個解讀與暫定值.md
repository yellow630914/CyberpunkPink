# 0009 M0 修正批次的幾個解讀與暫定值

- 日期：2026-11-22　狀態：採用；第 3、6 項的名字 2026-11-22 已定案

## 背景
這一批修 bug 與做定案時，有幾處規格的句子可以有兩種讀法，或規格還沒有給名字。這裡記下選了哪一種、為什麼。

## 決定

### 1. 「判定與寫正文之間一定隔著程式」怎麼驗（B006；AI_TASKS 2.2 節）
那一句後面接的是「AI 不能在同一步既決定結果又決定上限」。它要擋的是：判定說了什麼，寫正文就照著寫，中間沒有程式把它變成驗證、夾過的結果。
模板的格式檢查因此是：**寫正文的步驟只要（直接或間接）依賴一個判定的步驟，就要有一個程式的步驟夾在中間：寫正文依賴它，它依賴那個判定。**
- 寫正文可以同時直接依賴判定（要讀成功程度與轉折）。AI_TASKS 2.7 節自己的模板就是這樣：`text` 直接依賴 `judge`，也經過 `hint`（程式）→ `reward` 依賴它。
- 沒有採用「判定到寫正文的每一條路都要經過程式」：那會把規格自己的模板擋下。
- 只隔著別的 AI 步驟不算；程式排在判定之前也不算。
- 哪些任務算判定、哪些算寫正文，列在 `JUDGE_TASKS`、`TEXT_TASKS`（現在各一個）。之後有別的判定類任務（對方的行動、進不進場景）要不要算進來，等那些鏈搬進來再定。

### 2. 時間的條件照時段算（CORE_RULES 7.4 節）
「深夜 23～3 點，跨午夜，算在前一天的最後一段」。事件的時間條件（`weekday`）因此用時段算在哪一天（`segmentWeekdayOf`）：「週四深夜」到週五凌晨 3 點之前都成立（DOWNTIME 的「只在週四深夜」才排得出來）。
日曆的星期（`weekdayOf`，午夜換日）留給畫面與收租日用，和時段從幾點起算無關：第 1 天週二，第 7、14、21 天週一。
收租在週一的哪一刻結算，等帳單搬進來（M2）再定。

### 3. 內容篩選先放在存檔規則裡（標籤 id 已定案，2026-11-22）
UI 第 15 節：內容篩選跟著存檔走。完整的內容篩選在 M1 才搬；這一批只需要「身體的私密描寫」一格（私處的外觀受它控制）。
- 存法：`SaveRules.contentOff`（玩家關掉的標籤，沒列的都開著），和存檔規則一起清、一起存、用同一種變更改。M1 做內容篩選時沿用這個欄位。
- 這一格的標籤 id 是 `intimate_body`：**已定案**（2026-11-22），寫進 DATA 第 1 節的標籤表。
- 關掉時引擎不寫私處（草稿裡有也不存），不算錯誤。

### 4. 勢力與具名 NPC 的內容種類
出身的 `favor.choose_one` 與 `roster` 改收 DATA 1.1 節的 id，所以多了兩種內容：`faction`（id、全名、短名、類）與 `npc`（id、名字）。資料是從 DATA 1.1 節的表逐列轉的，出身對它們有引用檢查。
`npc` 現在只有 id 表；完整的格式（DATA 第 8 節）在 M2 補，補的時候加欄位、不改 id。

### 5. 角色的出身存在哪
`actor.ext.origin` 是一個物件，至少有 `id`（建角寫的還有 `favor`、`status`、`home`、`roster`）。存檔摘要讀 `id`，名字用內容查（W008）。之後讀出身的功能都照 `originIdOf` 讀。

### 6. 行動種類的資料多兩個欄位（鏈的 id 已定案，2026-11-22）
- `chain`：這種行動走哪一條任務鏈。沒寫就是自由行動的鏈；寫了別的鏈的種類先只是資料，那一條鏈搬進來之前不註冊成可以做的行動。3.5 節那一條鏈的 id 是 `adult_action`：**已定案**（2026-11-22），寫進 AI_TASKS 3.5 節。
- `hint_note`：參考範圍裡引擎現在還表達不了的部分（情報、物品、親密度、狀態……），照設計書的原文記下來，等那個系統搬進來再改寫成效果。
- 資料裡的 `free` 取代核心內建的自由行動（核心的登錄表只允許這一種取代）。

### 7. 提交時的年齡底線（W005）
讀檔掃整份狀態任何深度的 `age`；提交時改成掃整份報告（含掛鉤加進來的變更）。兩邊是同一條底線，提交得進去的一定讀得回來。
